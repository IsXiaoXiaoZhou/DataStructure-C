# 03_链栈

## 一句话定位

链栈用单链表装栈：top 就是链表头指针，进栈即头插，出栈即删头。它与顺序栈的分野在容量——结点按需 malloc，**没有满栈概念**，接口里连 is_full 都不设。

## 核心概念

单链表头部插删本来就是 O(1)，尾部才要 O(n)；栈恰好只在一端操作，选头部这端正合适。于是 push = 头插，pop = 删头，top 恒指向栈顶结点、空栈恒为 NULL。顺带回答两个"不需要"：不需要头结点——头结点的作用是让"在首结点之前插入"也能套用统一写法，而栈的插入永远发生在头部，没有这个特判需求；不需要尾指针——进出栈都轮不到链尾。

链栈把结构体定义藏进 .c，头文件只给 `typedef struct LinkStack LinkStack`。头文件注释解释了原因：**"top 恒指栈顶、空栈 NULL" 是需要维护的不变量**，结构体一旦暴露，调用方就能绕过 API 直接改 top，链序随时可能被弄坏。对照顺序栈——数组加下标，没有不变量要保护，才敢直接暴露结构体让你看 top 怎么移动。两页对照着读，"什么时候该用不透明指针"就有答案了。

`stack_destroy` 从栈顶逐结点 free：先用 next 暂存后继再释放当前结点——结点一旦释放，再读 node->next 就是访问已释放内存；最后释放栈头并置 NULL，防调用方误用悬垂指针。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 进栈 push | O(1) | 一次 malloc，头插两步 |
| 出栈 pop | O(1) | 摘头结点、取值、修 top、free |
| 取栈顶 / 判空 | O(1) | 判空条件 top == NULL |
| 求长 size | O(1) | 栈头存 size 计数，无需遍历 |
| 空间 | O(n) | 按需分配；满栈不存在，malloc 失败才报 DS_OVERFLOW |

## 易错点 / 考点

1. 头插两步的顺序：先 `node->next = stack->top`，再 `stack->top = node`。写反了新结点的 next 指向自己，原栈顶整条链丢掉。
2. 出栈的顺序：先摘结点、取值、修 top，最后才 free；free 之后还碰 node 就是悬垂访问。destroy 的循环同理——先暂存后继，再释放当前。
3. 王道爱考约定对比：无头结点派 top 指栈顶结点，栈空为 `top == NULL`；带头结点派 top 指头结点，栈空为 `top->next == NULL`。和顺序栈的 top 两派一样，先认约定再做题。至于"链栈要不要判满、要不要头结点"，答案都是不要，理由见核心概念。
