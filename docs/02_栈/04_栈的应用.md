# 04_栈的应用

## 一句话定位

括号匹配、表达式求值、递归三个经典应用。三件事共用一条规律：最近打开的必须最先收尾——栈的后进先出，在这里从存储结构变成了解题工具。

## 核心概念

括号匹配的靠山是一条不变量：**栈里存的永远是"还没等到配对"的左括号，而最新出现的左括号必然最先等到右括号**——这正是后进先出。扫描到左括号就连字符带下标入栈；右括号来了弹栈配对。三种失败对应三种结论：右括号来时栈已空，缺左括号；弹出的左括号类型对不上（如 "(...]"），类型不匹配；扫描结束栈里还压着人，缺右括号。bracket_match.c 把下标随字符一起压栈，三种出错都能报到具体字符的位置。

表达式求值走两阶段。中缀式难算，难在优先级、括号、结合性要边扫边权衡；后缀式把这些规则提前"编译"进顺序，求值只剩一遍线性扫描——先转后缀的理由就在这。阶段一用算符栈：操作数直接输出；遇运算符，把栈顶优先级大于等于自己的先弹出再压栈；遇右括号，弹到左括号为止。**"大于等于"里的等号管的是左结合**：少弹一个，5-3+2 会被转成 5 3 2 + -，算出 5-(3+2)=0，而正确答案是 4。阶段二用操作数栈：遇运算符弹两个数，先弹的是右操作数——8/4 弹反了就成 4/8。

递归的背后是系统调用栈：深入一层压一帧，返回弹一帧。factorial_nonrec 把这套机制搬到台面上——下行阶段把 n、n-1、…、1 逐层压栈，模拟递归深入；上行阶段逐层弹出累乘，模拟返回值向上传。**递归改非递归的通用思路就在此：系统隐式栈管的现场，换成显式栈自己管**。汉诺塔的 2^n - 1 步是问题固有规模，省不掉；斐波那契递归因子树大量重叠，调用次数膨胀到 O(2^n) 量级，迭代版只留相邻两项、O(n) 走完。

## 复杂度表

| 应用 | 时间 | 辅助空间 | 说明 |
| --- | --- | --- | --- |
| 括号匹配 | O(n) | O(n) | 单遍扫描，栈深最坏等于嵌套深度 |
| 中缀转后缀 | O(n) | O(n) | 操作数直出，每个算符进出栈各一次 |
| 后缀求值 | O(n) | O(n) | 单遍扫描，每个数压弹各一次 |
| 递归阶乘（显式栈版同阶） | O(n) | O(n) | 调用栈或工作栈深度为 n |
| 斐波那契递归 | O(2^n) | O(n) | 调用次数指数级；迭代版 O(n) 时间、O(1) 空间 |
| 汉诺塔 | O(2^n) | O(n) | 2^n-1 步是问题固有规模，递归深度仅 n |

## 易错点 / 考点

1. 中缀转后缀手算最常错在弹出时机：比较时只肯弹"严格大于"的，等优先级的压着不弹，左结合就破了（上面 5-3+2 那个例子，转成 5 3 2 + - 算出 0 而非 4）；右括号要弹到左括号为止，且左括号本身不进后缀式。
2. 后缀求值手算两个坑：弹两个数时先弹的是右操作数，减法除法弹反就差个负号、倒个数；多位数靠空格分 token，"10 2 -" 别读成 1、0、2。
3. 递归题分清"递归深度"与"调用次数"：阶乘两者都是 O(n)；斐波那契深度只有 O(n)（同时压栈的帧最多 n 层），调用次数却是 O(2^n) 量级——recursion.c 的 fibonacci_calls() 计数器就是让你跑一遍亲眼看这个差距的。
