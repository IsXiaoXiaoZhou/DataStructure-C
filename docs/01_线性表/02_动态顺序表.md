# 02_动态顺序表

## 一句话定位

把静态顺序表写死的数组换成堆上一块可 realloc 的内存，容量不够就倍增扩容——解决静态版"满 100 个就永远不能再插"的死板问题。

## 核心概念

静态表最憋屈的地方是容量写死在编译期。动态版把数据区搬到堆上，结构体多一个 capacity 记"已分配能装多少"，与 length（实际装了多少）构成恒不等式 capacity >= length。快满时先扩容再插入，"表满"在接口层面就不存在了。

扩容为什么选倍增而不是每次加一格？算笔账就明白：从容量 8 起每次翻倍，插到 1024 个元素时总共搬家 8+16+…+512 约 1000 次；若每次只加 1，同样插到 1024 个要搬 1+2+…+1024 约 52 万次。**倍增让 n 次尾部追加的总搬移代价是 O(n)，摊到每次就是均摊 O(1)**——头注释里"倍增扩容使尾部追加均摊 O(1)"说的就是这笔账。

这一篇的封装升级到不透明指针：头文件只剩一行 `typedef struct SeqList SeqList;`，data/length/capacity 的定义藏进 .c。原因文件头注释写得很直白——这三个字段之间存在不变量（扩容后 data 指针与 capacity 必须同步更新），外部若能绕过 API 野改字段，一次手滑就能让扩容后的指针失效。静态版敢露结构体、动态版必须藏，同一条规范两种选择，对照着读最见功力。

destroy 也从这一篇开始出现：`seqlist_destroy(SeqList **list)` 先 free 数据区再 free 表壳，最后 `*list = NULL`。传二级指针、销毁后自动置 NULL，调用方拿不到悬空指针，重复销毁也只是空操作。init 同样用二级指针出参带回新表，init_capacity 传 0 时内部取默认值 8；两层 malloc（先表壳后数据区），第二层失败会把第一层 free 掉再报 DS_OVERFLOW，不留半分配的残骸。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 按位取值 / 修改 get/set | O(1) | 与静态版同 |
| 尾部追加 | 均摊 O(1) | 偶尔触发倍增搬家 |
| 任意位置插入 / 删除 | O(n) | 搬移主导，扩容不改变量级 |
| 按值查找 find | O(n) | 顺序扫描 |
| 空间 | O(capacity) | 可能远大于 length，拿空间换免扩容 |

## 易错点 / 考点

1. **realloc 的返回值必须先接住再判断**：realloc 可能在原块后面没地方，另觅新块搬走数据。正确写法如代码 `int *new_data = realloc(list->data, ...)`，判空后才更新 list->data；若直接 `list->data = realloc(...)` 而分配失败，原块地址被 NULL 覆盖，旧数据整体泄漏。
2. "均摊 O(1)" 是分析题高频词：单次尾插最坏 O(n)（恰好触发扩容那次），但 n 次尾插总代价 O(n)，均摊每次 O(1)。两种说法都对，答题看问的是单次还是序列。
3. length 与 capacity 别混：print 出的 `length=5, capacity=8` 意思是装了 5 个、还能再装 3 个。概念题问"已分配空间大小"，答 capacity。
4. 手算扩容时机：判满条件是 `length == capacity`，扩容发生在搬移元素之前，扩后容量翻倍。给一串追加操作写每步 capacity 的题，常错在把扩容记成"插不下才补"。
