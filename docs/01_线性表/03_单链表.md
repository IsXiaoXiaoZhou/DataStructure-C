# 03_单链表

## 一句话定位

用"结点 + next 指针"把元素串起来，插删不再搬移半个数组——解决顺序表"中间插一个、后面全体挪窝"的痛。

## 核心概念

顺序表往表头插一个元素，1 万个数据要整体后移 1 万次；而且它开口就要一整块连续内存，存 10 万个元素时系统未必给得出。单链表把这笔账反过来算：每个结点自带下家的地址，逻辑相邻不再要求物理相邻，插入删除只改指针不搬元素，内存要一块给一块。

代价是丢掉随机存取：想知道第 5 个元素是什么，只能从第 1 个顺着 next 数过去。所以单链表快在哪，得先说清楚——**插入 / 删除本身只动两个指针 O(1)，但找到那个位置仍是 O(n)**，它的快是"定了位置的快"，与顺序表"按位取值 O(1)"的快正好互补。

本仓库的实现有两个值得对照源码读的选择。先是带头结点：表壳里嵌一个不存数据的 head，一切按位操作统一走"定位第 pos-1 个结点"（.c 里的 node_at），pos==1 时第 0 个结点恰好就是头结点，空表插第一个元素和表中间插完全同一套代码，零特判；判空也因此是一句 `head.next == NULL`。再看不透明指针：结构体定义在 .c 中，"头结点恒存在"这条约定，外部想破坏也够不着。

destroy 的写法是链表内存管理的第一课：逐结点释放必须先存 next 再 free（`next = curr->next; free(curr); curr = next;`），先 free 掉 curr 再读 curr->next 就是读已释放内存。头结点以值嵌在表壳里，随 `free(*list)` 一起走，最后 `*list` 置 NULL。另有 clear 只清数据结点、保留表壳可继续复用——destroy 与 clear 的分界就在"头结点保不保留"，头文件的 @note 特意写明了这点。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 头插 push_front / 头删 pop_front | O(1) | 头结点就是定位锚点，零特判 |
| 尾插 push_back | O(n) | 无尾指针缓存，先走到尾 |
| 按位插入 / 删除 | O(n) | 定位第 pos-1 个 O(n)，接链摘链本身 O(1) |
| 按位取值 get | O(n) | 无随机存取，从首元走 pos-1 步 |
| 原地反转 reverse | O(n) | 三指针一趟完成，额外空间 O(1) |

## 易错点 / 考点

1. **插入两步的顺序**：`node->next = prev->next; prev->next = node;` 必须先接后继。反过来先让 prev->next 指向新结点，原后继的地址就丢了，新结点的 next 只能指向自己成自环。手算画图就按"新结点先牵后家，前驱再牵新结点"的顺序走。
2. 删除必须先摘链再 free：`prev->next = target->next` 执行完 target 才能安全释放，顺序颠倒就是访问野指针。
3. 有无头结点是选择题陷阱：带头结点的空表是 `head->next == NULL`（head 本身永远在），不带头结点空表才是 `head == NULL`；带头结点在 pos==1 处插删无需特判——题目给哪种实现就按哪种答。
4. 反转手算：三指针每轮"存后继、掉头、双双右移"，最容易错在掉头前忘了存 next，链一断，后面整段全丢。
