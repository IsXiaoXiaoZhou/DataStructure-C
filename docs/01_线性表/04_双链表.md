# 04_双链表

## 一句话定位

给每个结点再配一条 prev 指针，让"已知结点求前驱"从单链表的重扫 O(n) 变成一跳 O(1)——源码注释原话说得更直白：这正是双链表的意义所在。

## 核心概念

单链表有个尴尬：你手里已经攥着第 pos 个结点，想删它、或问它前一个是谁，还是得从头再走一遍——单链只会往后看。双链表给每个结点加一条往回的路 prev，前驱后继都是一跳的事，代价是每结点多一个指针域、每次增删要多改两条链。

实现上有两个锚点要先立住。头结点仍以值嵌在表壳里，首元的 prev 恒指 &head，于是头部的双向接链和中间位置完全同构；再加一个 tail 指针，空表时指回 &head，非空恒指最后一个数据结点。tail 兑现的是尾插 O(1)（对比单链表尾插要走全表），代价是文件头注释点明的：每个改动尾部的操作都必须维护 tail 不变量。看 list_remove_at 尾部那个分支——删的若是尾结点，tail 要回退到前驱，删到空表还要退回 &head，增删代码里一半的心思都花在伺候这条不变量上。

PriorElem 是本模块的点题操作：list_prior_elem 定位到第 pos 个结点后，就一句 `*value = curr->prev->data;`。定位本身仍要从头走 O(n)（链表没有下标），但**"已知结点求前驱"这一步从 O(n) 掉到 O(1)**。顺带还有 list_print_reverse：从 tail 沿 prev 反向走到头结点，天然支持倒着打印——单链表想倒着看，只能先整表反转。

双向接链的手算顺序比单链表更要紧：先给新结点挂好两条腿（`node->prev = prev; node->next = prev->next;`），再动原链（后继回指、前驱改指）。新结点的 next 必须在 prev->next 被覆盖之前取到，这条纪律与单链表同源，只是要多守一条 prev。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 尾插 push_back | O(1) | tail 恒指尾结点，免遍历 |
| 求前驱 prior_elem / 求后继 next_elem | O(1) | 定位后 prev / next 一跳 |
| 按位插入 / 删除 | O(n) | 定位主导；接链要动 4 个指针域 |
| 按位取值 / 按值查找 | O(n) | 与单链表同 |
| 空间 | 每结点多 1 个指针 | 买回"往回走"的能力 |

## 易错点 / 考点

1. **插入要改 4 个指针域**：新结点的 prev、next，前驱的 next，后继的 prev——选择题常考这个数字。漏了后继回指 prev 这一步，就是给后面往回遍历埋雷。
2. 删除改 2 个指针域（前驱 next、后继 prev）；若删的是尾结点，还要同步 tail 回退——手算容易只画链、忘了尾指针。
3. 四步顺序：先挂新结点的两条腿，再让前驱后继回指。若先执行 `prev->next = node`，原后继地址丢失，node->next 只能接错。
4. 空表约定 tail == &head：空表尾插时 `node->prev = list->tail` 指的是头结点，与非空情形逻辑完全一致——手算空表尾插时别把 tail 当野指针。
