# 05_循环链表

## 一句话定位

让尾结点的 next 回指首元，整表成环，再用一个尾指针 rear 替代头指针——头插尾插都是 O(1)，约瑟夫环这类"走到头重新来"的问题也变成了它的主场。

## 核心概念

单链表只记头指针，想拿尾结点得走全表。循环链表换个记账方式：只存尾指针 rear，rear 恒指尾结点，而 **rear->next 恰好就是首元**——一个指针管两头。头插是把新结点塞进 rear 与首元之间、rear 不动；尾插塞进同一个位置、再把 rear 挪到新结点，两个函数的接链代码逐行相同，就差最后是否挪 rear 这一步。更妙的是按位删插不用特判首元：环里首元的前驱天生就是尾结点 rear，从 rear 出发走 pos-1 步定位前驱，pos==1 一视同仁。

环带来便利，也带来麻烦：链上没有 NULL 终点了。遍历、查找都不能写成单链表那套 `while (curr != NULL)`，否则就是死循环。本仓库的做法是按 length 计数走一圈立即停（代码注释原话：绝不能等 curr 绕回起点判断——那是死循环）；destroy 和 clear 则先把尾结点断环（rear->next 置 NULL），再按普通单链表逐结点释放。判空也随之换成 `rear == NULL`。

两表合并是 rear 表示法的招牌戏：list_merge 四步指针改接把两个环接成一个大环，不动任何结点、不遍历任何表，O(1) 完成——头指针表示法想做到这点，得先把 a 走到尾再接。main.c 里还有约瑟夫环求解：n=8、报数 m=3，出圈序列 3 6 1 5 2 8 4 7。约瑟夫问题为什么天然贴循环链表？因为报数报到圈尾要自动绕回首元，单链表得手工特判，环里这事免费发生；出圈者删除后其继任者顶替报数起点，下一轮出圈位置用公式 (cur + m - 2) % 剩余人数 + 1 直接算出。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 头插 / 尾插 | O(1) | 都插在 rear 之后，差一步是否挪 rear |
| 两表合并 merge | O(1) | 四次指针改接，不遍历不搬结点 |
| 按位插入 / 删除 | O(n) | 从 rear 出发定位第 pos-1 个结点 |
| 按位取值 / 按值查找 | O(n) | 按 length 计数走一圈即停 |
| 遍历 | O(n) | 计数控制，判 NULL 是死循环 |

## 易错点 / 考点

1. **遍历终止条件**：单链表判 NULL，循环链表的 NULL 永远等不到——要么按表长计数，要么 do-while 判"回到起点"。手算题和写代码题都在这里翻车。
2. rear->next 是首元，不是"尾结点的空后继"：看到 rear 别条件反射地往 NULL 想，环里首元的前驱就是 rear 本身；判空用 rear == NULL。
3. 约瑟夫手算差一：出圈位置公式是 (cur + m - 2) 取模再加 1，多减少减一位，出圈序列整串皆错。用 n=8、m=3 验一遍 3 6 1 5 2 8 4 7 最稳。
4. 单结点环：唯一的结点 next 指自己（`node->next = node`）；删掉它 rear 要置 NULL 回空表——"删到只剩一个再删"的手算场景最常被漏。
