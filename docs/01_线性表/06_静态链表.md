# 06_静态链表

## 一句话定位

用数组下标模拟指针，把整张链表装进一个定长数组——没有指针的语言也能把表"链"起来，也是把"逻辑结构不等于存储实现"看得最透的一篇。

## 核心概念

链表的本质是"每个结点记着下家在哪"，下家用内存地址（指针）表达只是其中一种方式。静态链表换用数组下标：分量的 cur 域存"下家在第几格"，**cur == 0 就相当于 NULL**。链式逻辑原封未动——插删只改游标不搬数据——但整张表躺在一块连续定长数组里。

妙处在两条链共用一个数组。看 list_init 的初始化：space[0] 是备用链表头，把所有空闲分量串起来，扮演"系统堆"；space[MAX-1]（下标 99）是数据链的头结点。插入时 sll_malloc_node 从备用链头摘一个空闲分量 O(1)，删除时 sll_free_node 把分量头插归还备用链 O(1)——malloc / free 的语义被完整模拟了一遍，刚归还的分量还会被优先复用。想通这一层，"结点的地址 = 数组下标、NULL = 0"就全通了。

和静态顺序表一样，它属于工程规范的例外条款：定长数组、无隐藏不变量，结构体（space 数组 + length）直接暴露在头文件，你能直接观察两条链在数组里的存储布局——list_print 特意把每个分量的下标一起打出来，就是让你看清游标链的真实走位。也正因为是栈对象、无堆内存，它的 destroy 只是复位：调一次 list_init 把两条链重置回初始态。这与动态版 free 两层、置 NULL 的 destroy 是两种完全不同的语义，对照着记。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 分配 / 归还分量 | O(1) | 备用链头摘下、头插归还 |
| 按位插入 / 删除 | O(n) | 沿 cur 定位 O(n)，接链摘链本身 O(1) |
| 按值查找 find | O(n) | 沿数据链顺扫，cur==0 收工 |
| 按位取值 | O(n) | 从下标 99 的头结点沿 cur 走 |
| 空间 | O(MAX_SIZE) | 定长 100 分量，无扩容 |

## 易错点 / 考点

1. **cur == 0 是 NULL，不是第 0 个元素**：手算时把游标 0 当有效下标去取 space[0].data，整条链就画歪了。另外本实现的头结点在下标 99（MAX-1），并非教材常用的下标 0——做题先看清题目自己的约定。
2. 插入是两步、缺一不可：先从备用链摘分量（space[0].cur 要跟着走），再把新分量挂进数据链。手算最容易漏第一步，分量"无中生有"就错了。
3. 删除必须归还分量：绕链之后调 sll_free_node 还回备用链。漏了这步，该分量既不在数据链也不在备用链，永久失联——静态链表版的"内存泄漏"。
4. 游标改动落在数组元素的 cur 域上，不是改某个指针变量：画图时每步都要写清"哪个分量的 cur 改成了几"，这是静态链表操作图的基本功。
