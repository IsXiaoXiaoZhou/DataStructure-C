# 01_静态顺序表

## 一句话定位

用一段编译期就定长的数组加一个长度变量实现线性表，解决"逻辑上相邻的元素，物理上也挨着放"这个最朴素的存储问题。它是理解顺序存储全部特性的最小样本。

## 核心概念

电影院一排连座，拿到座位号就直接走到位，不用一排排数——顺序表就是这种"位置算出来"的存储：data[0..length-1] 连续存放 a1..an，**逻辑相邻 ⇔ 物理相邻**，这是它区别于链表的核心特征。

本仓库刻意把这个特征摆在明面上：头文件直接给出结构体定义（`int data[SEQLIST_MAX_SIZE]` + `size_t length`），打开就能看到存储布局。为什么敢暴露？工程规范里有条例外条款——定长数组且没有隐藏不变量需要保护的结构，可以直接在 .h 露出布局。静态顺序表没有堆内存、没有指针一致性要维护，暴露了也无从破坏什么，换来的是教学上"一眼见真相"。对照下一篇动态顺序表的不透明指针写法，你会发现封装不是教条，而是"有没有不变量"的工程判断。

容量在编译期定为 100，没有动态内存，所以这一篇没有 destroy——无内存可泄漏，自然无需释放。代价是"满"变得真实：插满 100 个再插，insert 返回 DS_OVERFLOW，程序明确告诉你满了，而不是悄悄丢数据。每个操作返回 DsResult（状态码 + 可读消息），失败原因看 message 就懂，main.c 里的断言全部围绕这套状态码展开。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 按位取值 / 修改 get/set | O(1) | 首地址 + (pos-1)×元素大小，地址直接算出 |
| 插入 insert | O(n) | 平均后移 n/2 个元素 |
| 删除 delete | O(n) | 平均前移 (n-1)/2 个元素 |
| 按值查找 find | O(n) | 存储无序，只能从头顺扫 |
| 空间 | O(MAX_SIZE) | 编译期定死 100 格，装不满也占着 |

## 易错点 / 考点

1. **位序与下标差一**：接口的 pos 从 1 计，第 i 个元素存在 data[i-1]；插入合法范围是 [1, length+1]（上界相当于表尾追加），删除是 [1, length]。手算时把插入上界写成 length 是最常见的丢分点。
2. **挪动方向**：插入必须从最后一个元素起逐个后移（`for (i = list->length; i > pos - 1; i--)`），正向搬会覆盖还没挪走的数据；删除正好相反，从删除点起逐个前移补洞。
3. 满表即拒绝：`length >= SEQLIST_MAX_SIZE` 返回 DS_OVERFLOW。静态表没有"扩容"这个选项，这是它与动态版的第一条分界线。
4. "顺序表支持随机存取"要会论证：起始地址确定、元素等长，第 i 个元素的地址可以 O(1) 算出——选择题考这句推理，不是考背结论。
