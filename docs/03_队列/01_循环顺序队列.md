# 01_循环顺序队列

## 一句话定位

循环顺序队列把数组首尾"接"成一个环，front/rear 两个下标在环上循环移动。它解决的是顺序队列的假溢出：出队腾出的空位，不用搬移数据就能被后续入队复用。

## 核心概念

普通顺序队列里 front 和 rear 都只朝一个方向走：出队几次后数组前段空了一截，rear 还在往末尾爬，爬到头就报队满——前段的空位一个都没用上。这就是假溢出：不是没空间，是下标回不去。

解法是取模回绕：下标每次移动都 % MAX，越过末尾绕回 0，数组从一条路变成一个环，出队腾出的格子被绕回来的 rear 重新用上。本实现 front 指队头元素，rear 指队尾元素的下一格，都从 0 出发。

环形化带来新麻烦：判空是 front == rear，入队入到 rear 绕一圈追上 front 时也是 front == rear——空和满长得一模一样。出路只有两种：牺牲一格，或加标志位。**本仓库用牺牲一格法：满时留一个空格不入，判满写成 (rear + 1) % MAX == front，代价是 100 格只能装 99 个。**tag 法增设标志域区分空满，能用满 100 格，但每次入队出队都要多维护一个 tag，不变量更多更易写错，教学上取牺牲一格求简；考试两派都得认得。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 入队 enqueue | O(1) | 写 data[rear]，下标取模前移 |
| 出队 dequeue | O(1) | 读 data[front]，下标取模前移 |
| 取队头 queue_front | O(1) | 只读，下标不动 |
| 求长度 queue_size | O(1) | (rear - front + MAX) % MAX |
| 判空 / 判满 | O(1) | 各一次比较 |

空间是一个定长数组（MAX = 100，实际容量 99），无任何堆分配。

## 易错点 / 考点

- 判满条件分两派：牺牲一格派 (rear+1)%MAX==front，最多存 MAX-1 个；tag 派 front==rear 且 tag==1，能存满 MAX 个。"最多能存几个元素"这类填空，先看清题目按哪派出题。
- 元素个数公式 (rear - front + MAX) % MAX 里的 +MAX 不是摆设：环上 rear 可能绕到 front 前面（rear < front），不加 MAX 算出来是负数。
- 各教材 front/rear 语义不统一：本实现从 0 出发、rear 指队尾下一格；有的版本 rear 直接指队尾元素，公式整体差一位。套公式前先对约定，别背死一个。
- 手算时下标每次移动都要取模，最容易漏的是绕回 0 那一步——rear 算成 MAX 就越界了，后面全错。
