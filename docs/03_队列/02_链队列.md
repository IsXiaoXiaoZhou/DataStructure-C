# 02_链队列

## 一句话定位

链队列是带头结点的单链表实现的队列：front 固定指头结点，rear 指链尾，入队即尾插、出队即头删。没有容量上限，也不用像循环队列那样牺牲格子或搬数据。

## 核心概念

循环队列输在定长：数组开多大就最多排多长。链队列每个结点按需 malloc，队伍多长就链多长，queue_is_full 恒返回 0。结构是 `front → [头结点] → [a1] → … → [an] ← rear`，正确性全押在三条不变量上。

front 恒指头结点，头结点永不存数据。好处出队时最明显：队头元素在 front->next，删它永远是 front->next = first->next 一句，删完不管队列是否因此变空都不用特判。

rear 恒指链上最后一个结点，空队时与 front 同指头结点，所以判空条件 front == rear 和循环队列形式相同；入队也不用遍历找尾，新结点接在 rear 后面、rear 前移即可。

最要命的一条：**出队删到只剩头结点时，必须令 rear = front。**rear 本来指向被删的那个结点，free 之后它就是野指针，下一次入队写 rear->next 等于写已释放的内存；回位之后 rear 指着头结点，后续入队才接得对。link_queue.c 的 dequeue 里 if (first == queue->rear) 一句就是它，注释原话是"本模块最关键的一步"。

封装也是刻意的：struct LinkQueue 定义在 .c 而非 .h，调用方只拿到句柄，三条不变量外界想破坏都破坏不到。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 入队 enqueue | O(1) | 尾插，rear 直接定位 |
| 出队 dequeue | O(1) | 删 front->next，含删空回位 |
| 取队头 queue_front | O(1) | 读 front->next->value |
| 求长度 queue_size | O(1) | length 计数器，无需遍历链表 |

空间 O(n)：每个元素一个结点，比数组多付一个指针域的代价，换来无上限容量。

## 易错点 / 考点

- 出队到空再入队是高频考点：删空时漏了 rear = front，队列表面一切正常，下一次 enqueue 就写野指针。选择题爱问"删空后 rear 指向什么"——头结点。
- 判空 front == rear 依赖带头结点这个约定；不带头结点的写法判空是 front == NULL，出队删掉最后一个结点时还得把 front、rear 一并置 NULL。两套写法别混着背。
- destroy 从头结点开始逐个释放——头结点也是 malloc 出来的，漏掉就是泄漏——最后把 *queue 置 NULL，main.c 会断言句柄归零。
