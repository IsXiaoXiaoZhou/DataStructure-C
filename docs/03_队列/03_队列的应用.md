# 03_队列的应用

## 一句话定位

本页是队列的应用集合，目前收录舞伴问题：到场者按性别分成两个队列，每支舞曲两队队头各出一人配成舞伴。"先到先配"四个字，就是先进先出的直接翻译。

## 核心概念

舞伴问题一句话说全：舞者按到达顺序入场，男的一队、女的一队，每支舞曲开始时两队各从队头出一人配对；哪队先空，另一队剩下的就等下一支舞曲。

为什么非队列不可？配对规则是"第 i 个到的男生配第 i 个到的女生"，两队内部都按到达顺序逐个出场。用数组随手一存，配对时得靠下标数"第 i 个男生在哪"；用栈更不行，后到的反而先出，规则整个反掉。队列把到达顺序原样保存在队头到队尾的排列里：分队阶段按到达顺序入队，先到者自动排在队头；配对阶段每轮两队各出队一人凑成一对，谁都不用记"谁是第几个"。

落到本仓库的 dance_partner.c，算法分三段：先按性别把姓名各自入进男、女两个 static 数组队列；然后 while (两队都不空)，各出队一人配成一对；最后还留在队里的就是没配上的，按队头到队尾写进 DanceResult 的 leftover，main.c 拿它做断言，打印只是演示。

还有个取舍：这里用的是最朴素的"数组 + 头尾下标"，data[tail++] 入、data[head++] 出，没有取模回绕——每人只入队一次、出队一次，腾出的空位永远不会再被用到，回绕毫无意义；循环队列的取模是给同一块缓冲反复进出的场景准备的。姓名复制全用 snprintf 而非 strcpy：strcpy 不感知目标容量，超长或缺 '\0' 就越界写，snprintf 按 sizeof 限定字节数并保证结尾有 '\0'。

## 复杂度表

| 阶段 | 时间 | 说明 |
| --- | --- | --- |
| 按性别分队入队 | O(n) | 每人一次姓名复制 + 尾插 |
| 轮流出队配对 | O(n) | 每轮两队各出一人，共 min(男,女) 轮 |
| 收集剩余者 | O(n) | 未出队者按等待顺序报告 |

每人入队一次、出队一次，整体 O(n)；两套队列缓冲合计 O(n) 空间。

## 易错点 / 考点

- 王道常问"为什么用队列不用栈"：答案在 FIFO。配对按到达顺序，栈是后进先出，后到的先配，规则直接反掉；普通数组还得自己维护"第 i 个"的下标逻辑。
- 配对循环的条件是两队都不空（&&）。写成 || 的话某队空了还会继续出队，读到的是垃圾数据；手算时配对数等于较少一方的人数。
- 剩余者的输出顺序是队头到队尾，越早到的越靠前、越先等到下一支舞曲。手算别从队尾往前写。
