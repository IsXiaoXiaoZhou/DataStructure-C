# 01_邻接矩阵

## 一句话定位

用一张 n×n 的二维数组直接回答"u 和 v 之间有没有边、权是多少"——判边 O(1) 是它存在的理由，代价是空间固定 O(n²)，跟图里有多少条边没关系。

## 核心概念

矩阵的含义直白：`weight[u][v]` 存权值，没有边就放哨兵 `MG_INF`（0x3FFFFFFF，取在 int 上限一半以内，两个它相加也不会溢出，松弛运算可以放心做）。无向图加边对称双写、删边对称双删，矩阵始终保持对称。

有个实现层面的约定值得先看 .h：本仓库把无权图也统一当**权全为 1 的网**来存。好处是接口只有一套，加边、判边、DFS/BFS 对有权没权行为完全一致；判边就是跟 INF 比一次，不存在"0/1 矩阵"和"权矩阵"两套代码。

它的强项和短板绑在同一组下标上。判 (u,v) 有没有边，下标一访问就出结果，O(1)；可想知道 u 的所有邻居，得把整行 n 格扫完——u 哪怕只有一条边也得扫 n 格。所以矩阵版 DFS/BFS 是 O(n²)，跟边数无关。稠密图（e 接近 n²）这不亏，稀疏图就是花大量时间扫 INF 格，这时候该换邻接表（02 模块）。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 判边 / 取权 | O(1) | 直接下标访问，核心优势 |
| 加边 / 删边 | O(1) | 无向图对称双写、双删 |
| 邻域 / 度数 | O(n) | 扫一行，有向图入度扫一列 |
| DFS / BFS | O(n²) | 每个点找邻居都扫整行 |
| 空间 | O(n²) | 静态数组上限 100，与边数无关 |

## 易错点 / 考点

1. **n 个顶点 e 条边的无向图，矩阵中非 INF 元素恰为 2e 个**——选择题让数元素个数，报 2e 就走。
2. 判边是跟 INF 比较，不是判 0/1：本实现统一权 1 的网模型，做题前先看题目用哪种约定，两套结论别混背。
3. 无向图删边忘对称双删，矩阵不再对称，之后 `has_edge(u,v)` 和 `has_edge(v,u)` 会给出不同答案。
4. 空间 O(n²) 与边数无关：1000 个顶点哪怕只挂 100 条边，也得开 100 万格 int（约 4MB），稀疏图换邻接表立省一个量级。
