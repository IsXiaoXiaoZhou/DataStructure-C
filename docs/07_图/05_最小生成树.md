# 05_最小生成树

## 一句话定位

连通无向网里挑 n-1 条边把所有点连起来，总权还最小。Prim 从一个点出发"长大"，Kruskal 把边从小到大"挑便宜"——两个贪心方向相反，各有擅长的图的形态。

## 核心概念

两个算法路数相反，贪心却都成立，共用同一块地基：把点分成"已连入树"和"还没连"两堆，横跨两堆的最小那条边一定属于某棵最小生成树——不用它，把它换进任何生成树总权不会更大。这就是割性质，**每步取当前最便宜且不成环，不会堵死后路**——Prim 按树的边界割，Kruskal 按连通块割。

Prim 是"点贪心"：`lowcost[v]` 记 v 到当前树点集的最小边权，每轮挑树外 lowcost 最小者入树，再用它去松弛其余树外点，n-1 轮完事。每轮线性扫加全员松弛，O(n²)——它不排序、不看边，边再密也这个价，稠密图用它不亏。起点取 0 号点（代码里 lowcost 初值就是矩阵第 0 行），实现选择，不是算法要求。

Kruskal 是"边贪心"：全部边升序排序，依次尝试入选，用并查集查两端点是否已连通——同根说明再加这条边就成环，弃。选够 n-1 条提前收工。开销被排序主导，O(e log e)，边少的稀疏图比 Prim 的 n² 划算。并查集内置在本模块（路径压缩 + 按大小合并），与 06_树/07_并查集 同型。图不连通时两个算法都报 DS_ERROR，而不是输出一棵残树——判据分别是"某轮找不到可入树的点"和"选不满 n-1 条"。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| Prim | O(n²) | n-1 轮 × 每轮扫 lowcost + 松弛，与 e 无关 |
| Kruskal | O(e log e) | 排序主导，并查集均摊近 O(1) |
| Prim 空间 | O(n) | lowcost / nearest / in_tree 三个数组 |
| Kruskal 空间 | O(n+e) | 边表 + 并查集两个数组 |

## 易错点 / 考点

1. **Prim 换起点，总权值不变，树形态可能变**（有等权边时）：手算对答案报总权就行，别纠结从哪点起。
2. Kruskal 手算：排序后按序过边，两端已连通的边直接跳过，不是把边删了重排；选满 n-1 条就停，剩下的不用看。
3. 判环靠并查集"两端同根"，不是靠数边数——e 选到 n-1 条之前也可能中途出现环。
4. 考试爱问"两算法各适合什么图"：稠密图 Prim（O(n²) 与 e 无关），稀疏图 Kruskal（O(e log e) 吃边少的便宜）。
