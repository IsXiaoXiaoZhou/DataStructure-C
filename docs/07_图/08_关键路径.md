# 08_关键路径

## 一句话定位

AOE 网把工程画成"弧 = 活动（权即耗时）、点 = 事件"，要回答两个问题：整个工程最快多久完工、哪些活动一刻都拖不得。答案藏在最长路径里。

## 核心概念

先接受一个反直觉的事实：**工期是最长路径的长度，不是最短的**。一个事件要等它前面所有活动全部做完才发生，所以它的最早发生时间 ve 取各条来路的 max——最慢的那条来路说了算。顺着拓扑序正推取 max，推到汇点，ve[汇] 就是工程最短工期。在 06 模块练出来的"最短路"直觉，这里要整个反过来。

四个量两推两算。ve 正推取 max；vl（事件最迟发生时刻，拖过它就拖累整个工程）按逆拓扑序反推取 min，边界是 vl[汇] = ve[汇]；活动 (u,v) 的最早开始 e = ve[u]，最迟开始 l = vl[v] - w(u,v)。e == l 的活动时间余量为 0，一天都拖不得，是关键活动；关键活动串成的源到汇路径就是关键路径，它的长度正是工期。所以问"工期还能不能再压"，先看还有多少余量为 0 的活动。

本实现自带一遍 Kahn 拓扑并保留拓扑序：正推沿序扫，保证算 ve[j] 时所有前驱已就绪；逆推按序倒扫。它要求单源单汇——入度 0 和出度 0 的点各恰有一个，多源多汇直接报错（真实工程可以加虚拟超源超汇绕过）；活动耗时必须为正，0 和负数都不收。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 正推 ve | O(n²) | 拓扑序一遍扫描；邻接表实现 O(n+e) |
| 逆推 vl | O(n²) | 逆拓扑序一遍扫描 |
| 活动表（e/l/判关键） | O(n²) | 扫矩阵逐弧算，本质 O(n+e) |
| 空间 | O(n+e) | ve / vl / 拓扑序 / 活动表 |

## 易错点 / 考点

1. **ve 正推取 max，vl 逆推取 min**：新手顺着最短路径的思维正推取了 min，全盘皆错——事件早发生得等最慢的来路。
2. l = vl[v] - w(u,v)，减的是**弧头**事件的最迟时刻，写成 vl[u] - w 是高频错。
3. 关键路径不唯一：有等长路径时关键活动会分叉，未必串成一条单链。手算报"总工期 + 哪些活动 e==l"即可。
4. 缩短工期不是缩一个关键活动就行：多条关键路径并存时要一起缩；缩过头，原先有余量的活动反而成了新瓶颈。
