# 02_邻接表

## 一句话定位

顶点表配每顶点一条出边链表，空间 O(n+e)——稀疏图比邻接矩阵的 O(n²) 划算得多；代价是找某条特定的边得沿链扫，O(deg(u))。

## 核心概念

结构一眼能看懂：`first[u]` 指向 u 的弧链头，弧结点存 [adjvex | weight | next]。想知道 u 的邻居，沿链走，有几个走几步，一个格子都不浪费。这就是它和矩阵的根本取舍：**矩阵"判特定边快、找邻居慢"，邻接表"顺着邻居走快、找特定边要扫链"**。数字感受一下：1 万个顶点 2 万条边的稀疏图，矩阵要开 1 亿格 int，约 400MB；邻接表 5 万个结点，几 MB 的事。反过来稠密图 e≈n²，两者同阶，表还多背指针开销——稠密图回头选矩阵。

遍历序这里有个实现细节：本实现挂链走的是链尾（`append_arc` 扫到尾部再接），插入序即链序。这样按编号升序插边时，遍历序和矩阵法的"编号序"完全一致，两个模块能在同一张图上对拍 DFS/BFS 序。非递归 DFS 还有个小机关：邻居先收进临时数组再逆序压栈，出栈序才跟链序一致——栈是后进先出，正序压就反了。

两个遗留痛点正好引出后面两节：无向图一条边在两端各挂一个结点，删边要动两处（04 模块解决）；有向图只存出边，求入度得全表扫一遍 O(n+e)（03 模块解决）。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 空间 | O(n+e) | 无向图弧结点为 2e 个 |
| 加边 | O(deg(u)) | 沿链查重（重边合并为改权）后尾插 |
| 判边 / 删边 | O(deg(u)) | 扫 u 的链 |
| 邻域 | O(deg(u)) | 链上就是邻居，一格不多扫 |
| DFS / BFS | O(n+e) | 每条弧至多走一次 |
| 有向图求入度 | O(n+e) | 全表扫，十字链表的靶子 |

## 易错点 / 考点

1. **无向图邻接表的结点数是 2e 不是 e**；删边 (u,v) 要在 u、v 两条链各摘一次，漏一条就留下一根"单向的假边"。
2. 邻接表表示不唯一：边输入顺序不同，链序就不同，DFS/BFS 序跟着变。考试给"唯一遍历序"的说法别信；本实现靠尾插钉死顺序，只是为了可对拍。
3. 有向图出度沿链数就行，入度必须 O(n+e) 扫全表——考"为什么要有十字链表"，答的就是这句。
4. DFS 非递归版的邻居要逆序压栈，很多手写实现栽在出栈顺序和链序相反上。
