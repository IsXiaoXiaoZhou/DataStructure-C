# 讲解写作风格指南（像人一样说话）

本指南是 60 个模块页讲解内容的写作基准。参考对象：Hello 算法（hello-algo.com）的"痛点引入+因果链"风格、本仓库 README 的平实口吻。目标读者：零基础到备考王道的学生。

## 核心原则

1. **先讲痛点，再讲结构**。不从定义背诵进入。例：讲链表先说"数组要一整块连续内存，存 10 万个元素时系统未必给得出这么大的连续空间——链表的灵活性就体现在这里"，再定义链表是什么。
2. **句子之间有因果链**。上一句自然引出下一句，读者顺着读不需要回头。禁止无过渡的并列罗列（"它有以下三个特点：一…二…三…"是重灾区）。
3. **结论先行**。小节开头一两句给核心判断（"单链表插人是 O(1)，但找到插入位置仍是 O(n)——所以它的快是'定了位置的快'"），再展开为什么。
4. **复杂度配直觉数字**。不只写 O(n²)："1 万个元素冒泡一遍要比较约 5000 万次，这就是数据一大它就跑不动的原因"。
5. **"为什么"驱动**。教材结论背后的为什么最有价值：循环队列为什么要牺牲一个存储单元（不牺牲就分不清队空和队满）；哈夫曼为什么从最小两个开始合并（贪心保证小权值离根最远）。每篇至少有一个"为什么"讲到根上。
6. **类比一个就够**。顺序表=电影院连座、栈=叠盘子。一句话带过、服务理解，不展开成段子，不全篇堆类比。
7. **落在真实代码上**。本站区别于泛泛教程的价值：讲解要落到本仓库的实现上——不透明指针怎么读、destroy 为什么置 NULL、状态码怎么用。让读者"打开 .h 就能对上号"。
8. **考点写成"手算会错在哪"**。不做名词罗列。例："快排手算最常错的是分区的边界：j 扫到 pivot 值相等时停不停，直接决定后面是否死循环。"

## 语气

像学长在自习室给你讲题：平实、直接，偶带一句口语（"这里有个坑""记住这一点就行""很多人栽在这"）。可以有一两处轻轻的调侃，但不油腻。

## 禁止清单（AI 味重灾区）

- "综上所述"、"总而言之"、"值得一提的是"、"不难发现"、"由此可见"、"让我们"、"总的来说"
- "一方面……另一方面……"、"不仅仅是……更是……"、"既……又……"的对仗排比
- 每段结尾强行总结；每篇结尾强行升华（"掌握了 XX，你就打开了 XX 的大门"这类一句都不要）
- 全篇大量加粗（加粗只给每节最核心的 1~2 个结论）
- 三级以上标题堆砌；模板给定二级标题之外自创小标题
- 空话："在实际应用中具有重要意义"、"为后续学习打下坚实基础"
- 感叹号泛滥（全篇至多一个）

## 篇幅与结构

- 每篇正文 300~800 字，宁短勿水
- 填充范围：仅骨架页的"一句话定位 / 核心概念 / 复杂度表 / 易错点 / 考点"四处占位
- 复杂度表用 Markdown 表格（操作 × 时间/空间），3~6 行，别把每个函数都列全
- 一句话定位 1~2 句；核心概念 2~3 段；易错点/考点 2~4 条
- **绝不改动**：frontmatter、嵌码指令（`<<<` 行）、动画组件行、模板标题结构、"动手跑"节
