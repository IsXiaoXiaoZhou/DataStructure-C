# 数据结构教程站点设计文档

日期：2026-08-29
状态：已与用户逐节确认

## 背景与目标

仓库现有 9 大分类、65 个独立自包含的 C 数据结构模块（130 个 .c / 65 个 .h），
每个模块为 `xxx.h + xxx.c + main.c` 三件套，带教学型注释与断言测试。
目标是为这套内容建一个**数据结构教程站**：把 65 个模块的讲解、源码、
复杂度做成可浏览、可搜索的静态学习站点，配合严蔚敏/王道教材体系复习使用。

**核心设计原则：现有代码目录一字不动；源代码就是站点的数据源。**

## 非目标（本期不做）

- 不做在线编译/运行 C 代码（WASM 方案，过重）
- 不做部署 CI 与域名（产物为纯静态，将来上 GitHub Pages 只需加一个 workflow）
- 不做国际化（站点纯中文）

> 算法动画已按用户要求升级为正式需求，见下文"算法动画"章节。

## 技术选型

**选定：VitePress 1.x + Vue 3**（Node.js ≥ 18）。

| 候选 | 结论 | 理由 |
|---|---|---|
| VitePress | ✅ 采用 | 为文档站而生：Markdown 驱动、内置侧边栏/本地全文搜索/暗色模式/代码高亮(Shiki)/移动端适配；构建产物纯静态；用户有前端经验，可在 Markdown 中直接嵌 Vue 组件深度定制；dev 秒开 |
| Docusaurus | ❌ | 功能全但更重（版本化、博客等本项目用不上），构建慢；仅当主力栈是 React 时才优选 |
| Astro + Starlight | ❌ | 性能与框架无关性优秀，但生态较新、概念更多；VitePress 对本项目已够且更顺手 |
| 纯手写 / Next.js | ❌ | 65 个模块的目录、搜索、高亮全要自己造轮子；Next.js 为 Web 应用设计，对文档站是负担 |

依赖仅四个：`vitepress`、`vue`（站点）+ `vitest`（动画步骤生成器单测），
全部 devDependencies。

## 自动嵌码机制（核心）

用 VitePress 原生代码导入语法 `<<<`，不造轮子：

```md
嵌入完整文件：<<< ../01_线性表/01_静态顺序表/SeqList.h
嵌入行范围：  <<< ../01_线性表/06_树/06_哈夫曼树/HuffmanTree.c{30-52}
```

- 路径相对 md 文件指向仓库真实源码 → **代码与仓库永远同步**，
  改 C 代码后重新构建即更新，不存在"网页代码过期"
- 引用不存在的文件 → 构建报错，fail-fast 防路径写错
- 只展示某函数时在 C 源码中加 `// #region 名称` / `// #endregion` 标记
  （VSCode 同款语法，VitePress 支持，对 IDE 无干扰）
- 回退方案：若个别场景 `<<<` 对 srcDir 外路径解析受限（实现期验证），
  则写一个十几行的 markdown-it 插件在构建时读源文件，Markdown 侧接口不变

## 信息架构

**顶部导航**：首页 / 学习路线 / 工程规范 / 9 大分类（下拉直达）

**侧边栏**：`genSidebar.ts` 构建时扫描 `01_*`~`09_*` 目录自动生成
两级树（分类 → 模块页），以 `.md` 文件为准——没有对应 md 的模块不出现在
侧边栏，新增模块目录侧边栏自动跟上。

**模块页统一模板**（每篇 300~800 字）：

1. 一句话定位：这是什么、解决什么问题
2. 核心概念：设计要点、图示（如需要）
3. 复杂度表：各操作时间/空间复杂度（自定义 Vue 组件 `ComplexityTable`，样式统一）
4. 关键代码：自动嵌入的源码片段 + 行内讲解
5. 动画演示：`<Visualizer algorithm="xxx">`（有动画的模块，见下章）
6. 易错点/考点：王道考研高频陷阱
7. 动手跑：进入目录的 gcc 编译命令

**内置能力（零配置）**：本地全文搜索(minisearch)、暗色模式、移动端适配、代码块一键复制。

## 内容初建策略

65 篇讲解不可能一次写完，采用"骨架先行、逐篇填肉"：

1. 脚本生成全部 65 个模块的**骨架页**：统一模板结构 + 自动嵌码指令，
   讲解文字留醒目占位提示 → 站点立刻可浏览、可搜索、代码可见
2. 按学习路线（线性表 → 栈/队列 → …）逐篇填充讲解
3. 9 个分类概述页与 2 个 guide 页（学习路线、工程规范）随第一期完成
4. 动画按 V1→V5 批次迭代（见"算法动画"章节），每批完成后在对应模块页
   挂上 `<Visualizer>` 组件；已挂动画的模块在首页/分类页标注"含演示"

## 算法动画（可视化）

用户确认**全量覆盖**：线性类、排序 9 种、树类、图/最短路/KMP，以及查找类等
一切教学上有增益的模块（约 40 个动画）。逐批落地，但基建一次做对。

### 架构：录像-回放模式

把"算法执行"与"画面呈现"彻底分离，新增一个动画只需写一个纯函数：

```
输入数据 ─► 步骤生成器(纯 TS 函数) ─► 步骤序列[] ─► 播放器(通用 UI) ─► 场景渲染器(按形态复用)
             steps/bubbleSort.ts       {state,        播放/暂停/单步/    renderers/
             任意输入→逐步状态快照       highlight,    调速/进度/图例/     arrayBar.vue
             +高亮+解说文字             narration)    自定义输入          listNode.vue stackQueue.vue
                                                                      tree.vue graph.vue string.vue
```

- **步骤生成器**（`steps/*.ts`）：纯函数 `input → Step[]`，每个 Step 是完整
  状态快照（数据布局 + 高亮下标/节点 + 当前操作解说），不含任何 DOM。
  纯函数 → 可用 Vitest 单测步骤序列正确性，且天然支持**自定义输入**
  （用户改数据 → 重新生成步骤即可）
- **播放器** `PlayerShell.vue`（唯一）：控制条（播放/暂停/上一步/下一步/
  速度/进度）、解说字幕区、图例区、数据输入区；按帧渲染当前 Step
- **场景渲染器**（`renderers/*.vue`，6 类复用）：数组条形图（排序/查找）、
  链表节点箭头、栈/队列、树（SVG）、图（SVG 固定布局）、字符串双行。
  渲染器只认 Step 里的状态，不关心是什么算法
- 动画呈现**教材同款逻辑示意**（王道书上的图），不模拟真实内存指针，
  与讲解文字互相印证——教学价值优先

### 首批动画清单（全量规划，分批交付）

| 批次 | 动画 | 渲染器 |
|---|---|---|
| V1（基建+验证） | 排序 9 种：插入/希尔/冒泡/快排/选择/堆排/归并/计数/基数 | arrayBar |
| V2 | 单/双/循环链表插删、约瑟夫环、顺序栈/链栈进出、循环队列入出、两栈共享 | listNode、stackQueue |
| V3 | 二叉树前/中/后/层序遍历(含递归调用栈)、BST 插查、AVL 四种旋转、哈夫曼构造、线索化、并查集 | tree |
| V4 | DFS/BFS、Prim/Kruskal、Dijkstra、Floyd、拓扑排序、关键路径 | graph |
| V5 | BF/KMP 匹配与 next 计算、折半查找、散列冲突(拉链/开放定址) | string、arrayBar |

批次顺序理由：V1 用同一渲染器吃掉 9 个动画验证基建；之后每批至多引入一种
新渲染器。模块页与动画解耦，基建完成后可逐页添置。

## 质量保障

- **代码同步**：嵌码构建时读源文件，天然同步，零人工维护
- **完整性检查脚本** `docs/scripts/check-docs.mjs`：
  ① 每个模块目录都有对应 `.md`（缺失列出清单）；
  ② 所有 `<<<` 引用的源文件路径存在。
  本地 `npm run check` 可跑，将来可挂 CI
- **动画正确性**：步骤生成器是纯函数，用 Vitest 对每个动画的步骤序列
  做断言（如排序动画最终帧必须有序、比较/交换次数与手算一致）
- **Git 卫生**：忽略 cache/dist/node_modules（收编当前未提交的 .gitignore 改动）
- **讲解质量**：手写内容靠逐篇撰写与 review 保证，脚本只管"有没有"不管"好不好"

## 错误处理与边界

| 情形 | 行为 |
|---|---|
| `<<<` 指向不存在的文件 | 构建报错（期望行为，fail-fast） |
| 模块目录存在但无 md | 不进侧边栏；check 脚本报清单 |
| 源码后续重构改名 | `<<<` 路径失效 → 构建报错提示修复（比静默过期好） |
| 未来新增分类目录 | genSidebar 按通配扫描自动收录 |
| 动画自定义输入非法（超长/非数字） | 输入区即时校验提示，不生成步骤 |
| 动画步骤超长（如大数组排序） | 输入长度上限（排序类 ≤ 20 个元素），保证浏览器流畅 |
