# 06_哈夫曼树

## 一句话定位

同一批带权叶子，摆法不同总代价能差出一截。WPL（带权路径长度，Σ 权×路径长）最小的那棵就是哈夫曼树；哈夫曼编码让高频字符拿短码，靠的正是权大的叶子离根近。

## 核心概念

为什么每轮挑最小的两个合并？贪心理由可以说到根上：新合出来的父结点权是两子之和，它还要继续往上被合并——先合并的权值会被"叠加"更多次。权值越小心甘情愿待在深处，权值越大越要留在上层，总和才压得最低；把大权值塞进深处，大数字乘上长路径，WPL 立刻被拖垮。这也顺手解释了一条性质：**WPL 等于全部非叶结点权值之和**——每个内部结点的权正是一次合并的代价，所有合并代价加总就是总代价，与"合并果子"问题是同一道题。

手算 WPL 别一层层数深度。权 1,2,3,4：合并 1+2=3，再 3+3=6，再 4+6=10，WPL = 3+6+10 = 19，三笔加完收工。

实现用静态三叉数组：nodes[1..2n-1]，前 n 格是叶子（权值按输入顺序），后 n-1 格是每轮合并的新结点，每格 parent/left/right 存下标，parent 为 0 表示还是根、没被收编。select_two_min 每轮线性扫一遍"无双亲"的最小两个结点，小者为左；教学实现 O(n²) 够用，堆可优化到 O(n log n)。编码从叶向根回溯：当前结点是父结点的左孩子记 0、右孩子记 1，回溯完把位串反转——零 malloc，整棵树就是一段下标。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| 构造 | O(n²) | n-1 轮合并 × 每轮线性选最小（堆可到 O(n log n)） |
| 求 WPL | O(n²) 最坏 | 每叶向根回溯数深度 |
| 单字符编码 | O(l) | l 为码长，叶到根回溯再反转 |
| 位串解码 | O(位数) | 从根走到叶输出一个符号，回根重来 |
| 空间 | O(n) | 固定 2n-1 格，无指针无动态分配 |

## 易错点 / 考点

1. **哈夫曼树不唯一（左右子树可换、同权结点次序可换），但 WPL 唯一**。手算对答案比 WPL，别纠结树形。
2. 每轮是在"无双亲"的结点里挑最小两个，包括之前合出来的新结点：权 1,2,3,4 第二轮挑的是 3（新）和 3，不是 3 和 4。
3. n 个叶子的哈夫曼树共 2n-1 个结点、没有度为 1 的结点——选择题秒算总结点数就靠这条。
4. 编码回溯得到的是逆序位串，忘了反转全盘皆错；前缀码性质（任一编码不是另一编码的前缀）保证解码无歧义。
