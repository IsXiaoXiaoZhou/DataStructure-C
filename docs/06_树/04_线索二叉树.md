# 04_线索二叉树

## 一句话定位

想按中序"从任意结点直接走到下一个"，普通二叉链表要么重跑一遍带栈的遍历，要么给结点添父指针。线索二叉树选第三条路：n+1 个空指针本来就闲着，把它们捡起来存前驱后继，遍历从此不用栈、不用递归。

## 核心概念

先把账算清：2n 个指针域，n-1 条孩子边用掉 n-1 个，剩 n+1 个空。中序序列里 n 个结点恰有 n-1 对相邻关系，每对正好对应一条线索——用掉 n-1 个空域，首结点的 left、尾结点的 right 无处可指，保持 NULL。账目严丝合缝，这就是"废物利用"的全部家底。

麻烦在于一个域两种用途：left 可能指左孩子，也可能指前驱，读的人怎么分得清？答案是加两个标志位，ltag/rtag 取 0 表示孩子指针、取 1 表示线索。ThreadNode 比 BiTNode 多出来的就是这两个 int，**没有 tag，线索树寸步难行**——销毁函数 free_threaded 只敢沿 tag==0 的边递归，因为线索会把中序相邻结点连成环，顺着走就是死循环加 double free。

线索化的代码和中序递归遍历同构，只是"访问"结点 p 时多两步挂线：p 的 left 空就改成指向 pre（前驱线索）；pre 的 right 空就改成指向 p（pre 的后继线索）。pre 一路随参数传递，不用全局变量。

遍历为什么不用栈：求后继 tt_next 只有两 case——rtag==1，线索直达；rtag==0，后继是右子树的最左结点，沿 ltag==0 一路向左。两条路都不需要回头路信息，栈自然就省了。`for (p = tt_first(t); p; p = tt_next(p))` 就是完整中序遍历，空间 O(1)。

## 复杂度表

| 操作 | 时间 | 空间 |
| --- | --- | --- |
| 中序线索化 | O(n) | O(h) 递归栈 |
| 线索中序遍历 | O(n) | **O(1)**，对比普通遍历的 O(h) |
| 求中序前驱/后继 | 有线索 O(1)；顺子树找最左/最右 O(h) | O(1) |
| 逆中序遍历 | O(n) | O(1) |

## 易错点 / 考点

1. 手画线索二叉树，实线（孩子）和虚线（线索）必须按 tag 画；指认某结点的前驱后继时先看 tag 再看指针，别顺着箭头直接念。
2. **有右孩子时后继不是 right，是右子树的最左结点**（同理，有左孩子时前驱是左子树的最右结点）——考试最爱在这里埋坑。
3. 高频结论：中序线索树不加父指针即可双向遍历；先序线索可求后继；后序线索求后继必须父指针帮忙。
4. 线索化之后别再跑普通递归遍历——递归会顺着线索边闯进环里；销毁同理，只走孩子边。
