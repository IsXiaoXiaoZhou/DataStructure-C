# 07_并查集

## 一句话定位

n 个元素不断两两并成伙，还要随时回答"这俩是不是一伙的"——每次全表扫描 O(n) 顶不住。并查集把两个操作都摊到近乎 O(1)，它是 01 模块双亲表示法用到极致的样子：只找爹，永远不找儿子。

## 核心概念

数据结构朴实到不像话：一个 parent 数组，parent[x] 存双亲，根的 parent 指向自己，判根就认 parent[x]==x。所有操作都在向上爬。

先说清 union 的方向性，这是新手第一个坑：合并是**两棵树的根互相挂**（parent[ry] = rx），不是把元素 x 和 y 连起来。挂之前还得 find 两次拿根；若 rx==ry 说明本就同集，merged 返回 0、集合数不减——这个返回值到了 Kruskal 里就是"这条边会成环"的信号。

裸并查集最坏退化成一条链，find 要爬 O(n) 步，两个优化各管一半。按大小合并（size[] 仅在根上有意义，小树挂大树）保证树高 O(log n)；路径压缩负责压扁——本实现是两趟式：第一趟沿链找到根，第二趟重走一遍，把沿途结点全部直挂根。单次压缩多走一趟看似吃亏，但它让之后每次 find 一步直达，这笔账摊到整个操作序列上稳赚。两者合用，单操作均摊 O(α(n))，α 是反阿克曼函数——增长慢到 n 取天文数字也到不了 5，工程上直接当常数。

## 复杂度表

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| init | O(n) | 各自成根，size 全 1 |
| find | 均摊 O(α(n)) | 两趟：找根 + 沿途直挂根 |
| union | 均摊 O(α(n)) | 两次 find + O(1) 根挂根 |
| connected | 均摊 O(α(n)) | 两次 find 比根 |
| 空间 | O(n) | parent、size 两个数组 |

## 易错点 / 考点

1. **合并挂的是根不是元素**：写成 parent[x] = y 而不是 parent[ry] = rx，整棵树从此找不到根；size 比较也比的是两个根的 size。
2. 判根条件跟约定走：本仓库根自指 parent[x]==x，另一些教材根存 -1，做题先看题目约定。
3. 路径压缩后 parent 不再反映真实树形，"求树高/打印树形"的题不能带压缩做；集合元素个数靠根上的 size[] 维护。
4. 手算一串 union 序列画最终树，形状不唯一（两树等大时任挂方向都合法），但"谁和谁同集"唯一——答集合划分即可，别在形状上纠结。
