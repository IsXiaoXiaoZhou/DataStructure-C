# 04_稀疏矩阵-三元组


## 一句话定位

前面的公式压缩只对付有规律的矩阵，稀疏矩阵的非零元散落得没规律可循，干脆只存非零元本身：每个记成 (行, 列, 值) 三元组，按行序排进一张顺序表。非零元个数 tu 远小于 mu×nu 时，省下的内存是数量级级别的。

## 核心概念

存储形态：triples[0..tu-1]，每个单元是一个 Triple{row, col, value}，整张表按"行号增、行内列号增"排序。这个有序约定不是洁癖——转置、相加全部依赖顺序扫描，"按行序有序"是后面所有算法的前提。所以仓库里 Triple 是公开的纯数据包，SparseMatrix 主体却是不透明指针：不让外部乱序塞三元组破坏约定。

**普通转置为什么慢**。转置要把 (i, j, v) 搬到结果的 (j, i) 位置，可结果表也必须按行序排列，搬完不能乱。朴素做法是逐列收集：先扫全表找第 1 列，再扫全表找第 2 列……每换一列就从头看一遍 tu 个三元组，O(nu × tu)。慢的根源是"逐个找列"：每放一个元素都要重新问一遍"下一个第 j 列的在哪"。tu = 10000、nu = 1000 时是一千万次比较，只为搬一万个数。

**快速转置的 num / cpot 思想**。既然每列元素在结果表中的落位可以预先算出来，就不必反复找。第一遍扫描统计每列非零元个数 num[c]；据此递推每列首元的位置 cpot[c] = cpot[c-1] + num[c-1]（cpot[0] = 0——第 c+1 列前面挤着前 c 列的全部非零元）。第二遍扫描原表，每个三元组查 cpot 直接落进结果表，落一个该列 cpot 自增一次，给同列下一个元素让位。两遍扫描，O(nu + tu)，代价是多开两个长度 nu 的辅助数组——又是一次用空间换时间。

matrix_add 则是行序表的双指针归并：序小者原样抄入，位置相同者相加。这里有个经典考点：**和非零才存入，和为零不产生三元组**。5 + (-5) = 0，该位置在结果里是零元，而零元在稀疏存储中本就没有席位——"和的非零元个数可能少于任一加数"的根源就在这，结果表最多 ta + tb 个三元组，往往更少。

## 复杂度表

（mu×nu 为矩阵尺寸，tu 为非零元个数）

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| matrix_create | O(mu·nu) | 扫原矩阵一遍挑非零元 |
| matrix_get | O(tu) | 顺序查找，查不到即为零元、返回 0 |
| matrix_transpose | O(nu·tu) | 每列做一次全表扫描 |
| matrix_fast_transpose | O(nu + tu) | num/cpot 预定位，两遍扫描 |
| matrix_add | O(ta + tb) | 行序双指针归并 |
| 存储空间 | O(tu) | 每个非零元一个三元组 |

## 易错点 / 考点

- cpot 递推的下标：cpot[c] = cpot[c-1] + num[c-1]，是拿**上一列**的个数累加，写成 num[c] 整张表错一位。落位后还要 cpot 自增——忘了自增，同列第二个三元组会和第一个挤在同一格。手算快速转置题基本都栽在这两处。
- 普通转置的复杂度别背成 O(nu + tu)：它是"每列扫全表"，两层循环相乘 O(nu·tu)。判断方法很简单：内层扫描次数依不依赖外层，依赖就是乘。
- 转置结果的行数列数要交换：mu 行 nu 列转完是 nu 行 mu 列。手算写结果矩阵时漏交换规模，后面全错。
- 加法抵消：同位置相加为 0 时不产生三元组，两个游标都要前进。问"结果三元组个数"，答"最多 ta+tb，可能更少"，别答固定值。
