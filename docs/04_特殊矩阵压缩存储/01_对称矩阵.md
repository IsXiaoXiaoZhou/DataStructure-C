# 01_对称矩阵


## 一句话定位

n 阶对称矩阵满足 a(i,j) == a(j,i)，上三角和下三角是同一份数据的镜像。存两遍纯属浪费，于是只存下三角（含主对角线）的 n(n+1)/2 个元素，压进一个一维数组——1000 阶矩阵从 100 万个存储单元降到 50 万零 500 个。

## 核心概念

压缩存储的本质是一笔交易：**用下标换内存**。存的时候丢掉重复的那一半，要用的时候靠一条映射公式把矩阵下标 (i, j) 算回一维下标 k。这条公式是本模块唯一的难点，也是后面几篇的共同套路，值得推一遍。

按行序存下三角，数组长这样：data = [a11, a21, a22, a31, a32, a33, ...]，第 1 行 1 个、第 2 行 2 个、第 i 行 i 个。求 a(i,j)（i ≥ j）的位置，先问一句：第 i 行前面已经排了多少个？1+2+...+(i-1) = i(i-1)/2 个，这正是第 i 行第一个元素的起点；再在行内偏移 j-1 步（再减 1 是因为数组下标从 0 计），得到

```
k = i(i-1)/2 + j - 1
```

拿 a31 验证：它前面排着第 1、2 行共 3 个元素，k = 3×2/2 + 1 - 1 = 3，手点数组 [a11, a21, a22, a31] 确实是 data[3]。

那 i < j 的上三角元素呢？利用对称性 a(i,j) == a(j,i)，交换 i、j 后套同一个公式，让它落到下三角的镜像单元。这个设计有个顺带的好处：matrix_set(i, j) 天然同时改写 (i, j) 和 (j, i)，**对称性在存储层面就不可能被破坏**，不用靠使用者自觉。

落到代码上：行列号从 1 开始（教材惯例，和数学记号 a_ij 一致），传 0 会得到 DS_OUT_OF_RANGE；结构体是不透明指针，映射公式藏在 .c 里，对外只有 create/get/set/print/destroy 五个函数，打开 .h 就能对上号。

## 复杂度表

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| matrix_create | O(n²) 时间 | 要扫一遍原始 n×n 矩阵 |
| matrix_get | O(1) 时间 | 纯下标算术，无遍历 |
| matrix_set | O(1) 时间 | 顺带改写镜像位 (j,i) |
| 存储空间 | n(n+1)/2 | 约为按 n² 整存的一半 |

## 易错点 / 考点

- 1-based 和 0-based 混淆。公式按教材惯例行列号从 1 算，算出的 k 才是 0 起点的数组下标——代 (1,1) 得 0 就是在验证这一点。题目若给 0 起点的行列下标，先各加 1 再代公式，直接代必错。
- i、j 代反。公式里 i 是行号。手算时拿 (3,1) 这类"行大于列"的验一下：k 应为 3；代出别的值，多半是行列写反了。另外 i < j 时必须先交换再代。
- 反向考法：给 k 反求 (i, j)。先定位行——满足 i(i-1)/2 ≤ k 的最大 i（等价于 i(i-1)/2 ≤ k < i(i+1)/2），再用 j = k - i(i-1)/2 + 1 收尾。手算最容易在行边界的"取不取等号"上翻车。
- 数个数：下三角（含对角线）共 n(n+1)/2 个元素，选择题常直接问压缩数组长度，别和三角矩阵的 n(n+1)/2 + 1 记混（差的那 1 个是常数 c，下一篇讲）。
