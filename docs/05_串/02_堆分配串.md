# 02_堆分配串

## 一句话定位

把定长版的数组换成堆上一块按需 realloc 的缓冲区，赋值连接永远不会"满"——三种存储里唯一容量无上限的一版，代价是从此有了 destroy 和泄漏风险。

## 核心概念

结构体只剩两个字段：`char *ch` 加 `size_t length`。init 之后 ch 为 NULL、length 为 0，空串连一次分配都不发生；首次 assign 时 `realloc(NULL, n)` 等价 malloc，后续每次都由统一的 ensure_capacity 把缓冲区扩到恰好够用。这里有个与动态顺序表不同的选择：那边容量倍增、为反复尾插摊平成本，这边**每次按需分配到刚好**——因为串操作是整串为单位的，assign/concat 一次写入的长度事先已知，不存在逐字符追加的场景，按需分配省心又省内存。hs_clear 也顺了这个思路：只把 length 归零、缓冲区留着，下次 assign 免一次分配。

与定长版还有一处易忽略的差异：堆版在 assign/copy/concat/substring 末尾都补了 '\0'。length 仍是串的权威信息，这个终止符纯粹是顺手送个方便——缓冲区可以直接当只读 C 字符串传出去，main.c 里 hs_to_cstr 之外的 strcmp 断言全靠它。

真正值得细看的是 concat 的重叠防护。接口里 dst、a、b 是三个独立参数，拦不住调用方传同一个串，main.c 偏就测了 `hs_concat(&s, &s, &s)`。直接写会发生什么：realloc 扩容可能搬家，旧块被释放，dst 与 a 共享的那块内存随旧块一起没了，再从 a 拷贝就是读已释放内存。所以实现先把 a、b 的内容 malloc 备份到安全地带，再扩容、再从备份写入。destroy 则是标准收尾：free 后置 NULL，free(NULL) 合法，重复 destroy 无害——main.c 里连销毁两次的断言都有。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 赋值 assign | O(n) | realloc 到恰好够用，整块复制 |
| 复制 copy | O(n) | 同上 |
| 连接 concat | O(n) | 含一次备份与一次扩容 |
| 求子串 substring | O(len) | pos 合法范围 [1, length] |
| 比较 compare | O(min(len_a, len_b)) | 逐位比公共前缀 |
| 空间 | O(n) | 恰好 length+1 字节，无预分配浪费 |

## 易错点 / 考点

1. **生命周期多了 destroy**：init/assign 过的串必须 destroy，忘了就是泄漏——这是堆分配版与定长版在用法上最大的区别。free 后字段置 NULL，重复销毁安全。
2. realloc 的返回值必须先接住再判断：失败时返回 NULL 但**原块不动**；直接 `s->ch = realloc(...)` 会拿 NULL 冲掉原地址，旧数据整体丢失。ensure_capacity 的写法就是标准答案。
3. concat 自连陷阱：dst 与 a/b 同串时，先备份再扩容。手写时直接从 a 拷到 dst，realloc 一搬家内容就没了。
4. 空串有两种形态：init 后 ch == NULL，clear 后 ch 非 NULL 但 length == 0，判空逻辑两种都得认。"串零分配"是面试里聊得起来的细节。
