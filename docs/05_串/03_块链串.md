# 03_块链串

## 一句话定位

串的链式存储——但结点里装的不是单个字符，而是 CHUNK_SIZE 个字符的一小块。它是在"链表不用整块内存"与"串的存储密度"之间找平衡的产物。

## 核心概念

先看单字符链表有多亏：每个结点 1 字节有效数据配一个指针（教材按 4 字节算），存储密度只有 1/5，绝大多数内存花在指针上。块链串的思路是让一个指针摊多个字符：CHUNK_SIZE=4 时密度升到 4/8=1/2，链长也缩短到四分之一。**CHUNK_SIZE 就是权衡旋钮**——调大，指针开销占比更低、密度更高，但结点分配粒度变粗，尾块不满时浪费的槽位也更多；调小，浪费少、链又碎又长。教材考这个参数，考的就是这笔账。

结构是头尾双指针加 length。tail 指向尾结块，使尾部追加不必从头数起——append_char 只看 `length % CHUNK_SIZE`：尾块没满就写下一个槽，满了才 malloc 新块，均摊 O(1)。assign/copy/concat/substring 全部复用这个辅助函数逐字符重建链，块管理逻辑只写一遍。按位取字符则要现算：第 pos 个字符位于第 (pos-1)/CHUNK_SIZE 块的第 (pos-1)%CHUNK_SIZE 槽，顺链走过去——链表没有随机存取，位置是"数"出来的，不是"算"出来的。

一处教学化偏差要知道：教材示意图的尾块用 '#' 把空槽补满，本实现**不写入填充符**，有效性完全由 length 和块内已用槽数管理。bs_print 输出的 '|' 只是块边界示意。读图时记牢：'#' 是示意符号，不算串的成分。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 尾部追加 append_char | 均摊 O(1) | tail 直达尾块，满了才开新块 |
| 按位取字符 bs_get | O(⌈n/CHUNK_SIZE⌉) | 顺链走过 block_idx 个结块 |
| 赋值 / 复制 / 连接 / 求子串 | O(n) | 统一走 append_char 逐字符重建 |
| 比较 compare | 最坏 O(n²/CHUNK_SIZE) | 每个字符单独 bs_get 走链取值 |
| 空间 | O(⌈n/4⌉·(CHUNK_SIZE+指针)) | 每结块 4 字符摊一个指针 |

## 易错点 / 考点

1. **存储密度计算**：密度 = 串值占用 / 结点总占用。单字符结点 1/(1+4)=1/5，CHUNK_SIZE=4 时 4/(4+4)=1/2。选择题给 CHUNK_SIZE 求密度，最容易忘掉的就是那个 next 指针也占字节。
2. 跨块换算差一：CHUNK_SIZE=4 时第 5 个字符在第 2 块第 1 槽——(pos-1)/4 和 (pos-1)%4，直接拿 pos 去除会错位。main.c 的 bs_get(&s, 5) 断言的就是这个边界。
3. 尾块有效槽数 = length % CHUNK_SIZE；结果为 0 且 length>0 说明尾块恰好满。遍历读源串时不能把无效槽当数据——bs_copy 用 length 提前收口，就是防这个。
4. 工程上认识它即可：真实文本处理几乎都在顺序存储上做，块链串的价值在于把"存储密度"这个概念具象化，考试考概念多于考实现。
