# 04_朴素模式匹配

## 一句话定位

模式匹配的笨办法，也是一切改进的基准线：把模式串对齐主串的每个起点逐字符比，失配就整体右移一格从头再来。教材叫 Index(S,T,pos)，也叫 BF（Brute-Force）算法。

## 核心概念

流程一句话说完：主串 S 长 n、模式串 T 长 m，对齐起点从 1 试到 n-m+1，每个起点上逐字符比较，全比上就命中返回 1-based 起点，中途失配就换下一个起点。

它的命门在**失配之后**。拿最坏情况的原型看：主串 8 个 'a'，模式 "aab"。起点 1：'a'、'a' 都对，第三位 'a' 对 'b' 失败——前两次比较的信息全扔掉，主串指针退回起点 2、模式串归位重头再来。又比三次，又在第三位失败……每个起点都打满 3 次比较，总共 (8-3+1)×3 = 18 次，恰好打满 O((n-m+1)·m) 这个最坏上界。放大了看：主串 1 万字符、模式 1 千字符，最坏约 900 万次比较；同样的场景 KMP 只需 1.1 万次上下（见 05 模块）。

主串指针 i 为什么甘愿回退？因为 BF 没有任何预处理，"模式串下一步该从哪继续"这个问题它答不上来，只能保守地全部重来。可失配那一刻其实藏着信息：前 j-1 个字符都匹配上了，说明主串失配点前面那段就是模式串的前缀 t[1..j-1] 本身——"接着从哪比"只取决于模式串自己的前缀结构。BF 把这笔现成的信息扔了，KMP 捡起来算成表，这正是两篇的分界线。

本仓库的实现还有个值得琢磨的细节：代码用 start + i 计算实际比较位置，变量 i 从不往回赋值——写法上省掉了"i 回溯到 i-j+2"这个动作，但重复比较一次没省，本质仍是回溯。bf_index_count 把比较次数暴露出来，main.c 对高重复串实测这个数，拿它和 05 模块的 KMP 对比最直观。

## 复杂度表

| 场景 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 最好情况 | O(n) | 首个起点即命中，n 次比较收工 |
| 最坏情况 | O((n-m+1)·m) ≈ O(n·m) | 高重复主串，每个起点比到末位才失败 |
| 空间 | O(1) | 无预处理，只有几个下标变量 |

## 易错点 / 考点

1. **回退位置**：教材 1-based 记法下失配时 i 回到 i-j+2（本次对齐起点的下一位）、j 归 1。手算模拟最常错成 i-j+1——退回同一起点，直接死循环。
2. 起点上界 n-m+1：剩下不够 m 个字符就不用比了。循环条件写成 i <= n 会在主串尾部越界比较。
3. 最坏情况的构造：主串高度重复（全 'a' 或周期串），模式串"前 m-1 位好匹配、第 m 位才失配"。选择题问哪种串让 BF 退化到最坏，按这个形状想。
4. 返回值约定：命中返回 1-based 位置，未命中返回 0。空模式约定命中位置 1，两者在 main.c 断言里都有。
