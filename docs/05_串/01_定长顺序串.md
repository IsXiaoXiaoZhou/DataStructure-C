# 01_定长顺序串

## 一句话定位

串是内容受限的线性表——元素限定为字符，操作集也从"单点插删"换成了"整串赋值、连接、比较、定位"。定长顺序串用一段编译期定长的字符数组加一个 length 实现它，是串的三种存储里最朴素的一版。

## 核心概念

结构本身没有任何新东西：`char data[STR_MAX_SIZE]` 加 `size_t length`，data[0] 存第 1 个字符，与静态顺序表同源。真正的区别藏在两处。一是 **'\0' 不参与存储**：教材的串靠 length 显式记长，不依赖终止符，所以 ss_print 按长度逐字符输出，而不是当成 C 字符串打印——data 尾部并没有 '\0'，对它调 strlen 是未定义行为。C 语言的字符串只是串的一种实现约定，别把两者划等号。

二是超长策略。教材的定长串在赋值、连接超出 MAXSTRLEN 时是**静默截断**——多的部分悄悄扔掉。本仓库刻意改成报错：ss_assign 先数长度，超过 STR_MAX_SIZE 直接返回 DS_OVERFLOW，源码注释原话是"宁可报错也不静默截断"。原因很实际：截断丢数据不吭声，调用方毫无感知，等发现串短了一截，错早就埋下了。读代码时记住这是一处**教学化偏差**，考概念题按教材答"截断"，读本仓库代码按 DS_OVERFLOW 理解，两套别混。

容量编译期定死、没有动态内存，所以这一篇和静态顺序表一样没有 destroy——无内存可泄漏，clear 只需 length 归零，残留字符在逻辑上已不可达。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 赋值 assign | O(n) | 先查容量再整块复制，超长报 DS_OVERFLOW |
| 复制 copy / 连接 concat | O(n) | concat 先判 a 长 + b 长是否溢出 |
| 求子串 substring | O(len) | pos 合法范围 [1, length]，越界拒绝 |
| 比较 compare | O(min(len_a, len_b)) | 先比公共前缀，全同再比长度 |
| 定位 index | O((n-m+1)·m) 最坏 | 朴素匹配，见 04 模块 |
| 空间 | O(STR_MAX_SIZE) | 定死 100 字符，装不满也占着 |

## 易错点 / 考点

1. **超长处理两派**：教材定长串连接超长时截断（选择题按教材答），本仓库返回 DS_OVERFLOW（读代码按报错理解）。知道有这个分歧，答题先看题目问的是教材还是这份实现。
2. '\0' 不入串：length 不含终止符，data 不保证以 '\0' 结尾。想导出标准 C 字符串得自己补终止符——下一篇堆分配串就是这么做的。
3. 位序差一：ss_substring 的 pos 从 1 计，合法范围 [1, length]，实际读 data[pos-1]。求子串时 pos+len-1 超过 length 即越界拒绝。
4. 串比较规则：先逐位比公共前缀，前缀全同再比长度，短者小——"abc" < "abcd"。不是把字符 ASCII 加起来比大小，main.c 里 "abc" 与 "abcd" 的断言考的就是这条。
