# 05_KMP算法

## 一句话定位

模式匹配的正解：对模式串做一次 O(m) 预处理，把"失配后模式串从哪继续"提前算成 next 表，匹配时主串指针 i 永不回退，总复杂度 O(n+m)。本章也是考试的重点难点。

## 核心概念

接上一篇的账：BF 浪费的是失配前已匹配的那段信息。而那段信息其实写在模式串自己身上——主串失配点前面的 j-1 个字符，就是模式串前缀 t[1..j-1] 的逐字符拷贝。"接着从哪比"只取决于这段前缀的结构，与主串其余部分无关。既然只跟模式串有关，就可以在匹配开始前对每个 j 算好答案，这就是 **next 数组：失配后 j 应回退到的位号**。

本仓库沿用教材 1-based 约定：**next[j] = t[1..j-1] 的最长相等前后缀长度 + 1**，next[1] = 0，next[2] 恒为 1。为什么是"长度+1"？设最长相等前后缀长 k，它的意思是"主串失配点前 k 个字符恰好等于模式串开头 t[1..k]"，于是 j 直接放到 k+1、拿着 t[k+1] 跟主串失配位继续比，i 一格不退——这就是"主串指针不回退"的全部机制。next[1]=0 则是"首字符就失配"的信号：j 归 0，主串右移一格重来。

手算方法用王道原例 "abaabc" 走一遍（main.c 断言的就是这组数）：逐位看 t[1..j-1] 的最长相等前后缀——

- j=3：t[1..2]="ab"，前缀 a 对后缀 b 不等，长 0 → next[3]=1
- j=4：t[1..3]="aba"，前缀 a = 后缀 a，长 1 → next[4]=2
- j=5：t[1..4]="abaa"，长 2 的 ab≠aa，退而其次 a=a → next[5]=2
- j=6：t[1..5]="abaab"，长 3 的 aba≠aab，长 2 的 ab=ab → next[6]=3

得 next = 0 1 1 2 2 3。手算时从长到短试前后缀，等上了别停，还要确认没有更长的——"最长"两个字才是易错处。

nextval 是在 next 上的第二次打磨。跳到 next[j] 之后，拿去跟主串失配位比的是 t[next[j]]；如果 t[next[j]] == t[j]，而 t[j] 正是刚失配的那个字符，这一比注定又失败——白比一次。既然必败，不如一步到位：**nextval[j] 直接继承 nextval[next[j]]**。看 "aaaab"：next = 0 1 2 3 4，nextval = 0 0 0 0 4，连续四个 a 的无效跳转被一次折完。"abaabc" 的 nextval = 0 1 0 2 1 3。注意继承前必须先比较，不相等就照抄 next[j]。

实现层面：next 表是模式串"自己跟自己跑一遍 KMP"算出来的（get_next 里 i、j 都在模式串上走）；表保持教材 1-based，代码内部访问字符时统一减 1 换 0-based。匹配循环里失配执行 j = jump[j+1] - 1——但 nextval 的优化链可能把值折到 0，此时只能 i 右移、j 归 0，直接减 1 会让 size_t 下溢，match_core 对此单独分支处理，这是两套下标混用最容易埋雷的地方。O(n+m) 的来历是均摊分析：i 只进不退至多加 n 次，j 的每次跳转都在减小、总增量不超过总减量，跳跃总量被 n 兜住。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| get_next 预处理 | O(m) | 模式串自匹配一遍 |
| get_nextval | O(m) | 在 next 上一趟扫过 |
| 匹配 kmp_index | O(n) | i 只进不退 |
| 总计 | O(n+m) | 对比 BF 最坏 O(n·m) |
| 空间 | O(m) | next/nextval 各一张表 |

## 易错点 / 考点

1. **next 手算差 1**：next[j] 是"回退到的位号"（前后缀长度+1），不是长度本身。两个锚点自查——next[1]=0、next[2]=1；手算填出 next[2]=0 或 next[3]=2，多半就是差了这 1。
2. **两派记法先认派**：本仓库与王道/严蔚敏是 1-based（next[1]=0，next[0] 槽位弃用）；另有 0-based 派（next[0]=-1，整表数值差 1）。题目给出 next 表让你求 nextval 时，沿用题目那派，别拿另一派的公式硬套。
3. nextval 继承有条件：t[next[j]] == t[j] 才继承 nextval[next[j]]，否则 nextval[j] = next[j]。"abaabc" 的 nextval 错成 0 1 0 2 0 3 之类，多半是没比较就一路继承。
4. 失配时动的是 j：j = next[j]，i 原地不动；j 已经是 0 才 i++。手算模拟匹配过程时把 i 也一起挪了，后面全盘对不齐。
