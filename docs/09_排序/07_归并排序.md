# 07_归并排序

## 一句话定位

分治模板：折半拆到单元素，再把两条有序串合并成一条——合并像拉链，两边都有序，拉一次线性时间，O(n log n) 就是这么挣来的。

## 核心概念

合并（merge_range）是全部的关键：两条有序段各持一个游标 i、j，每次比较谁小谁进 tmp，游标前移；一条耗尽，另一条整段接上。每层归并合计 O(n)，折半拆分共 log n 层，总计 O(n log n)，最好最坏一个样——归并不看输入的脸色。动画单步看一次 merge，两条游标一咬一合，比文字直观。

稳定性在那个等号上：`a[i] <= a[j]`，相等时取左半边的。左半边元素在原数组里本来就排在右半边前面，先来者先走，次序保住；写成 `<`，右半边的同值元素会抢跑到左半边前面，稳定就破。这是插入、冒泡之后第三次在比较符号里见到稳定性了，规律记死：**相等时偏向原本在前的那一边，就稳定**。

O(n) 辅助空间是代价：merge 要 tmp 数组中转再回写，这是它和快排（原地分区）最实际的差别。本仓库给了两个版本：merge_sort 递归自顶向下；merge_sort_iter 自底向上，width 从 1 起逐轮翻倍，不递归、省栈。想要 O(n log n) 还要稳定，常用内排序里归并几乎是唯一选项——快排、堆排都不稳定，这句在选择题里反复出现。

## 复杂度表

| 场景 | 复杂度 | 说明 |
| --- | --- | --- |
| 最好/最坏/平均 | O(n log n) | log n 层 × 每层 O(n) |
| 空间 | O(n) | tmp 辅助数组（递归栈另有 O(log n)） |
| 稳定性 | 稳定 | 相等取左半边 |
| 2 路归并趟数 | ⌈log₂n⌉ | 每趟 O(n) |

## 易错点 / 考点

1. **手算 merge 会错在收尾**：一边耗尽后，另一边剩余的整段要原序抄进 tmp，漏抄是最常见的模拟错误；相等时取左，取右就错。
2. "n 个元素 2 路归并需要几趟"：⌈log₂n⌉ 趟；迭代版第 k 轮结束时段长 2^k，问"某趟后有几段有序"按这个数。
3. 空间答 O(n) 指辅助数组；递归栈 O(log n) 是另一笔账。选择题给"空间复杂度 O(n)"就是标准答案。
