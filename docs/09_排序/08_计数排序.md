# 08_计数排序

## 一句话定位

前面的排序都在两两比较，计数排序根本不比：数出每个值出现几次，按值的顺序倒回数组——拿值当下标，绕开了比较排序 O(n log n) 的下限。

## 核心概念

为什么能突破下限：比较排序的下限来自决策树——n 个元素有 n! 种排列，每次比较只有两种结果，分辨所有排列至少要 log₂(n!) ≈ n log n 次比较。计数排序不做比较，直接拿元素值当数组下标（count[v]++），信息取自"值本身"，下限对它无效。代价也卡在同一个地方：**关键字必须是非负整数且值域不大**，O(n + max_key) 里的 max_key 一大（比如给 10 个 32 位数排序），count 数组先爆掉。

实现三步走（counting_sort.c 注释里写的就是这个）：频次统计 → 前缀和 → 从右往左回填。前缀和之后 count[v] 是"≤ v 的元素个数"，也就是值为 v 的元素在输出里占据的最后一个槽位；从右往左扫原数组，先碰到的（原位置靠右的）同值元素占最后槽，靠左的自然落在前面——**同值元素保持原有次序，稳定**。换成从左往右回填，同值次序会反过来，稳定就没了。

这份实现的约定：调用方必须传 max_key，元素为负或超上界直接返回 DS_OUT_OF_RANGE，不做隐式扩容——.h 注释里"关键字为非负整数，且已知上界 max_key"说的就是这个。动画单步走一遍，重点盯回填那几步的方向。

## 复杂度表

| 指标 | 复杂度 | 说明 |
| --- | --- | --- |
| 时间 | O(n + k) | k = max_key + 1，量纲与比较排序的 n log n 不同 |
| 空间 | O(n + k) | count 数组 + out 数组 |
| 稳定性 | 稳定 | 从右往左回填 |
| 适用前提 | 非负整数、值域可控 | k 太大得不偿失 |

## 易错点 / 考点

1. **手算会错在前缀和的含义**：做完前缀和的 count[v] 是"≤ v 的个数"（1 基的末槽位置），不是"= v 的个数"；回填时先存 out[count[v]−1] 再把 count[v] 减一，两步顺序写反就下标越界。
2. "最坏情况下时间复杂度与 n 同数量级的排序"这类选择题，值域与 n 同阶时答案选计数排序——它压根没有 n log n 这一项。
3. 为什么要写稳定版（从右往左回填）而不是按 count 直接展开输出：因为它是基数排序的底层零件，下一趟排序必须继承上一趟的次序。
