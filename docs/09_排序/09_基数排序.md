# 09_基数排序

## 一句话定位

把整数按位拆开，从最低位到最高位（LSD）逐位做一次稳定计数排序，d 趟之后整体有序——从头到尾没比较过两个完整的数。

## 核心概念

LSD 的正确性押在一个事实上：第 k 趟只按第 k 位分桶，位相同的元素谁前谁后完全沿用上一趟的次序。所以**每趟的排序必须稳定**，否则低位的功夫全白费——这正是上一篇"从右往左回填"的稳定计数排序的用武之地，radix_sort.c 每趟调用的就是同款三步（频次 → 前缀和 → 从右往左回填）。d 趟（d 为最大值的位数）走完，高位是主键、低位是次级键，整体有序。

位与桶的权衡落在 base 这个旋钮上：一趟成本 O(n + base)，趟数 d ≈ log_base(maxv)。base 调大，d 变小，但桶数组变大、前缀和变长；base 调小则相反。本仓库把 base 做成参数（要求 ≥2）：处理 32 位整数时取 base = 256，只要 4 趟、桶也就 256 个计数——**空间换趟数，拧的就是这个旋钮**。

实现细节看 radix_sort.c：`digit = (a[i] / cur) % base` 抠出当前位，cur 每趟乘 base；负数不支持（发现负值直接返回 DS_OUT_OF_RANGE），要排负数得先分正负两堆或整体加偏移。动画单步走一趟，看个位相同的元素是不是守住了原始次序。

## 复杂度表

| 指标 | 复杂度 | 说明 |
| --- | --- | --- |
| 时间 | O(d(n + base)) | d = 最大值的位数 |
| 空间 | O(n + base) | out + count |
| 稳定性 | 稳定 | 每趟都是稳定计数 |
| 趟数 | d 趟 | base 越大 d 越小 |

## 易错点 / 考点

1. **手算会错在"位相同时的次序"**：给几个数问按个位排完后的序列，个位相同的必须和上一趟次序一致（稳定）。基数排序的模拟题几乎都埋这一个坑。
2. d 与 base 的换算题：base=2、maxv=7，d = 3（二进制 111 三位）；公式 d = ⌊log_base(maxv)⌋ + 1。
3. 为什么从最低位开始（LSD）而不是最高位：LSD 只要每趟稳定就能一路叠上去；MSD 要按最高位分桶后在桶内递归排次高位，实现重得多。王道考 LSD，方向别背反。
