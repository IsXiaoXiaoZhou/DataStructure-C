# 05_简单选择排序

## 一句话定位

每趟从未排序区间扫出最小值的下标，与区间头部做一次交换——思路最朴素的排序，也是写操作最省的简单排序。

## 核心概念

机制一句话说清：第 i 趟线性扫一遍记下最小值下标 min，然后最多一次交换把它换到 a[i]。它和插入排序的分工值得记一笔：**选择排序的比较死板（不管输入多有序，恒扫 n(n−1)/2 次），但交换至多 n−1 次**——插入最坏要搬约 n²/2 次数据，冒泡最坏也要 n²/2 次交换。元素大、写代价高的场景（比如写 flash），少写就是硬道理。

为什么不稳定：交换是远距离的，a[i] 和 a[min] 中间隔着一串元素，换位时会跳过同值元素。经典反例 [3a, 3b, 1]：第一趟 min 指向 1，交换后变 [1, 3b, 3a]，3a 越到了 3b 后面。代码里 `if (min != i)` 的守卫只省掉无谓的自交换，救不了稳定性——只要发生交换就可能越位。

动画单步看两趟就够：每趟注意 min 指针怎么在扫描中更新，以及末尾那次唯一的交换。

## 复杂度表

| 场景 | 复杂度 | 说明 |
| --- | --- | --- |
| 最好/最坏/平均 | O(n²) | 比较次数与输入无关 |
| 交换次数 | 至多 n−1 | 简单排序里最少 |
| 空间 | O(1) | 原地 |
| 稳定性 | 不稳定 | 远距离交换越位 |

## 易错点 / 考点

1. **手算会错在"每趟确定谁"**：第 i 趟把第 i 小的放到 a[i]，前缀逐位有序；别和冒泡"最大值沉底"的结论方向搞混。
2. 判断题重灾区："选择排序每次把最小的选出来放前面，所以稳定"——错。稳定性看的是同值元素是否越位，远距离交换照样越，[3a, 3b, 1] 一例足以推翻。
3. "比较次数不随输入变化的排序有哪些"：简单选择排序是标准答案（恒 n(n−1)/2 次）；对偶问题"交换次数最少的简单排序"也选它。
