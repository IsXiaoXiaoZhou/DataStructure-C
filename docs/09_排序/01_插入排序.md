# 01_插入排序

## 一句话定位

摸扑克牌时手里的牌始终有序，每摸一张从右往左找个位置插进去——直接插入排序就是把这套动作写成代码，专治小规模和基本有序的数据。

## 核心概念

代码只有一层 for 套一个 while：i 从 1 走到 n−1，a[0..i-1] 永远有序，key = a[i] 是新摸的牌；while 从右往左把比 key 大的牌统一右移一格，腾出的位置 a[j] 正好放 key。注意实现是"移位"不是"交换"——key 先抠出来，空位靠覆盖腾出，比每次 swap 少一半赋值。读 insert_sort.c 时别把 `a[j] = a[j - 1]` 误认成交换。

为什么基本有序时接近 O(n)？关键在 while 的进入条件 `key < a[j - 1]`：新牌只要不比左边的小，循环体一次都不进，这一趟只花一次比较、零次移动。基本有序的数组里大多数趟都是这个形态，全程约 n 次比较就收工；换成逆序输入，每张牌都要顶到最左边，移动次数约 n²/2。对输入顺序敏感，是它和后面选择排序最大的分别。

稳定性同样藏在符号里：`key < a[j-1]` 是严格小于，相等的牌不会被越过去，所以稳定；手滑写成 `<=`，同值元素会互越，稳定破功。下面的动画支持单步，拿默认数据走几步，盯着 key 怎么把大牌一路往右推。

## 复杂度表

| 场景 | 复杂度 | 说明 |
| --- | --- | --- |
| 最好（已有序） | O(n) | 每趟一次比较、零移动 |
| 最坏（逆序） | O(n²) | 移动次数约 n²/2 |
| 平均 | O(n²) | 期望比较约 n²/4 |
| 空间 | O(1) | key 一个暂存 |
| 稳定性 | 稳定 | 严格小于，同值不越位 |

## 易错点 / 考点

1. **手算会错在移动方向**：插入是"比 key 大的右移"，key 左边的有序段本身不动。模拟题给某趟结束的序列时，先检查 a[0..i-1] 是否仍有序——这是最快的判错依据。
2. "移动次数最少"的选型题：基本有序选直接插入（或冒泡），逆序选简单选择（交换至多 n−1 次）。注意题目问的是移动/交换还是比较，两个指标的答案经常相反。
3. 折半插入排序只把"找位置"换成二分，比较次数降到 O(n log n)，移动次数没省，整体仍是 O(n²)——选择题爱考"折半插入省了比较、没省移动"。
