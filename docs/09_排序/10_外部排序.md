# 10_外部排序

## 一句话定位

内存装不下 10 GB 的文件时，内排序那套全部失灵——外部排序改走流水线：分批排成有序段写回磁盘（初始归并段），再用多路归并合成一个全局有序的大文件。本页四个模块对应这条流水线的四个环节。

## 核心概念

先看全流程，再看每个环节省的是哪一笔账。外部排序真正的瓶颈是磁盘 I/O 而不是 CPU：数据每多一趟读写，总时间就成倍地涨。所以后面几个模块的目标一致——减少归并趟数、减少被反复读写的记录量。

生成初始段：最朴素的做法是"读满内存排一段"，每段长度 = 工作区大小 m。置换选择排序（replacement_selection.c）聪明得多：输出堆顶最小值后立刻从输入补一条进来，新记录 ≥ 刚输出的就进堆续在本段，否则先"沉淀"到 deferred 区留给下一段。像滚雪球——当前段的门槛带着新记录一路抬高，段越滚越长，**随机输入下平均段长约 2m**；最好情况输入正序，一段到底；最坏逆序，每段恰 m。

多路归并的每次选择：k 个有序段各亮出段头，要选全局最小。挨个比是 k−1 次，败者树（loser_tree.c）压到 log₂k：完全二叉树的叶子是各段当前值，内部结点只记败者、树根挂最终胜者；新值上岗后沿父链重比一遍即可——**路径上存的都是败者，新胜者必然在这条链上产生**。读尽的段置 INT_MAX 永不取胜（external_merge.c 的 EOF 语义正是如此），胜者变 INT_MAX 就是全部合并完成的信号。

段的长短不一（置换选择造成）时，先归并谁影响 I/O 总量：把哈夫曼的答案搬过来——短的先合、放深层，长的靠后。k 叉归并树要求每个内部结点恰有 k 个孩子，每合并一次段数减 k−1，所以段数 S 必须满足 (S−1) % (k−1) == 0；不满足就补 u = (k−1) − (S−1)%(k−1) 个长度为 0 的虚段，虚段放在最先归并的位置（它不产生真实 I/O）。opt_merge_wpl 用最小堆模拟 k 路哈夫曼，把归并树的带权路径长（= 全部记录被读写的总次数）算出来，手算题对着这个数校答案。

## 复杂度表

| 环节 | 复杂度 | 说明 |
| --- | --- | --- |
| 置换选择生成初始段 | O(n log m) | 工作区堆调整主导，段均长约 2m |
| 败者树建树 / 单次调整 | O(k) / O(log₂k) | 每选一个全局最小的代价 |
| k 路归并一趟 | O(n log₂k) | n 为总记录数 |
| 归并总趟数 | ⌈log_k S⌉ | S 为初始段数，k 越大趟数越少 |
| 最佳归并树求 WPL | O(S log S) | 最小堆模拟 k 路哈夫曼，S 为段数 |
| 内存开销 | O(k + m) | 段头 + 工作区，与 n 无关 |

## 易错点 / 考点

1. **手算败者树会错在"败者"二字**：内部结点存的是比较中输掉的段号，不是赢的；调整时新值沿父链向上、每层只与存着的败者比一次。把树理解成"存胜者"，整道题就歪了。
2. 补虚段数 u = (k−1) − (S−1) % (k−1)，注意先取模：S=8、k=3 时 (8−1)%2=1，补 2−1=1 个虚段；u=0 就不补。常见错误是拿 S 对 k 直接取模。
3. "平均段长 2m"的前提是输入随机：正序输入一段到底，逆序输入每段恰 m。题目给了具体序列时老老实实模拟，别背平均值。
4. k 越大越好吗：趟数变少、I/O 减少，单次选择代价 log₂k 的上涨被趟数抵消（总比较量级不变）；但 k 路需要 k+1 个输入缓冲区，内存装不下才是真正的上限。
