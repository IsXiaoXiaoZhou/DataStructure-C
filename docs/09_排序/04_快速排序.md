# 04_快速排序

## 一句话定位

每轮选一个基准 pivot，一趟分区把比它小的甩到左边、比它大的甩到右边，pivot 落进最终位置，再对左右两半递归——实践中通常最快的比较排序，partition 也是笔试面试的头号手算题。

## 核心概念

本仓库用 Lomuto 分区（quick_sort.c 的 partition）：pivot = a[hi]，i 是"≤pivot 区"的下一个坑位，j 从 lo 往右侦察，碰到 a[j] ≤ pivot 就把它和 a[i] 换、i 前进一格。手算走一遍，a = [2, 5, 3, 8, 1, 4]，pivot = 4：

- j=0：2≤4，a[0] 与 a[0] 自己换（等于没换），i→1
- j=1：5≤4？不，i 不动
- j=2：3≤4，a[1]↔a[2]，变 [2, 3, 5, 8, 1, 4]，i→2
- j=3：8≤4？不
- j=4：1≤4，a[2]↔a[4]，变 [2, 3, 1, 8, 5, 4]，i→3
- 扫完，a[3]↔a[5]（pivot 归位），得 [2, 3, 1, 4, 5, 8]，返回 3

全程不变量：i 左边永远 ≤ pivot，i 到 j−1 之间永远 > pivot。页面下方的动画把每步 j 的比较和换位都画了出来，拿默认数据单步走一遍，比背文字快得多。

为什么平均 O(n log n)、最坏 O(n²)？pivot 切得均匀，每层分区合计 O(n)，递归 log n 层，总量 O(n log n)。但 pivot 是拿输入碰运气：**输入本来有序（或逆序）时，pivot 每次都是最值，区间每轮只缩 1 个，n 层递归累计约 n² 次比较**——分区一边倒。median_of_three（三数取中，把 a[lo]/a[mid]/a[hi] 的中位数换到 hi 当 pivot）是给有序输入上的保险，但极端输入依然构造得出来，理论上界还是 O(n²)。

不稳定的原因是跨距离交换：a[i] 和 a[j] 中间隔着一段"＞pivot 区"，换位时会跳过若干元素。比如 [3a, 3b, 1] 取 1 做 pivot，最后的归位交换把 3a 甩到 3b 后面。这个锅在"远距离 swap"上，比较条件写成 ≤ 还是 < 都救不回来。

## 复杂度表

| 场景 | 复杂度 | 说明 |
| --- | --- | --- |
| 最好/平均 | O(n log n) | 每轮切半，递归 log n 层 |
| 最坏 | O(n²) | 有序输入分区一边倒 |
| 空间 | O(log n) | 递归栈；一边倒时退化到 O(n) |
| 稳定性 | 不稳定 | 跨距离交换 |
| 原地性 | 原地 | 分区就在原数组上做 |

## 易错点 / 考点

1. **手算分区最常错在两处**：一是 j 扫到与 pivot 相等的元素——本实现 `a[j] <= pivot` 会把它换进左区；二是一趟结束后 pivot 落在下标 i（先与 a[hi] 交换归位），不是留在 hi。题目让写"一趟 partition 后的序列"，这两点直接决定对错。
2. "一趟之后数组有序吗"——不，每趟只有 pivot 一个元素就位。选择题问"k 趟后至少几个元素在最终位置"，按每趟恰好一个 pivot 归位数。
3. 空间答 O(log n) 依据的是递归栈深，不是辅助数组；分区一边倒时栈深 O(n)，所以判断题"快排空间复杂度最坏 O(n)"是对的。
4. 三数取中只降低最坏情况的概率，不改变最坏上界——"三数取中保证 O(n log n)"这类说法是错的。
