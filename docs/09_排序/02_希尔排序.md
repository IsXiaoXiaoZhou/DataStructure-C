# 02_希尔排序

## 一句话定位

直接插入排序对乱序数据慢，慢在元素只能一格一格挪；希尔排序让它先跨大步：按步长分组做插入，步长逐轮减半，最后一轮才是普通插入。

## 核心概念

分组方式看代码就明白：gap 从 n/2 起步，下标相差 gap 的元素算一组，组内做插入排序；把插入排序里的 1 全换成 gap（`j -= gap`、`key < a[j - gap]`），就是 shell_sort.c 的全部秘密。之后 gap 减半再来一轮，直到 gap = 1——那一轮是一次货真价实的直接插入排序。

为什么跳着排能变快？插入排序的瓶颈是元素一步只能挪一格，离终点 1000 格的元素要挪 1000 次。大步长的组内插入让元素一次跨 gap 格，**大步消除小位移**；等 gap 收到 1 时，数组已经被前面几轮捋得基本有序——而"基本有序时插入接近 O(n)"正是上一篇的结论，希尔排序等于把这条性质当武器使。下面的动画单步看一轮大 gap，能明显看到元素在长距离搬家。

增量序列决定快多少：本仓库用最朴素的 n/2, n/4, …, 1（Shell 原始序列），最坏仍是 O(n²)；换成 Hibbard（2^k−1）一类的序列能压到 O(n^1.5) 左右。不稳定也是分组带来的：同值元素可能分在不同 gap 组里被先后挪动，相对次序就乱了。

## 复杂度表

| 场景 | 复杂度 | 说明 |
| --- | --- | --- |
| 最坏 | O(n²) | Shell 原始增量的短板 |
| 平均 | O(n log n) ~ O(n^{3/2}) | 随增量序列浮动，没有公认的精确界 |
| 空间 | O(1) | 原地 |
| 稳定性 | 不稳定 | 跨组移位越过同值元素 |

## 易错点 / 考点

1. **手算会错在"一轮 gap 排完什么"**：一轮只保证每个 gap 子序列各自有序，不保证前 gap 个位置是全局最小的 gap 个。模拟题给 gap=2 一轮后的结果，按组（下标 0,2,4… 一组、1,3,5… 一组）逐组检查才不会错。
2. 判断题"希尔排序最后一轮一定是一次直接插入排序"——对，gap=1 那轮就是，前面的轮全是预处理。
3. "为什么希尔排序至今没有精确的复杂度"：答案挂在增量序列上，不同序列界不同，教材也只给范围。概念题别把它和快排的 O(n log n) 并列硬背。
