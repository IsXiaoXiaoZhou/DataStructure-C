# 10_散列表-拉链法

## 一句话定位

冲突了就往桶的链表上挂：每个桶是一条单链表，同义词全堆一处。删除痛快、表可以超载，是理解散列"期望 O(1)"最直观的冲突处理方案。

## 核心概念

散列函数再均匀，冲突也躲不掉，关键是冲突之后元素往哪放。拉链法的答案最直白：桶数组每个槽位挂一条单链表，H(key) 相同的"同义词"全串在同一条链上，桶里装不下？不存在的事，链要多长接多长。插入用头插法 O(1)——先沿链查重，没有再让新结点站到队首；查找就是先算桶号、再沿链逐个比；删除定位后摘链 free，利利索索。

这套做法的性能账也很好算。装填因子 α = n/m，直觉上就是**平均每个桶挂几个元素**：α=0.7 时每条链期望 0.7 个结点，查找期望比较 1+α/2 次成功、α 次失败，α 翻倍性能就平缓地降一档，不会崩。更实用的一点是 α 没有 1 的上限——元素个数超过桶数照样能工作，表超载了性能平滑变差而不是插入失败。代价在别处：每个结点多一个指针的空间开销，链表结点散在堆上、缓存不友好，以及每次插入都要 malloc。

对照源码有两处值得看：hc_init 里 p 取 prev_prime(m)，配合上一篇"为什么用素数"；hc_search 带 `cmp` 出参精确统计比较次数，hc_delete 摘链时 prev/cur 双指针"先把后继接到前驱上再 free"，和单链表删除的写法一脉相承。12 篇的 hp_chain_asl 会拿这套结构算精确 ASL，本篇的 cmp 就是它的原料。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 插入 | O(1+α) | 沿链查重 + 头插 |
| 查找（成功） | O(1+α) | 命中位置期望在链前半段 |
| 查找（失败） | O(1+α) | 把那条链扫完，期望 α 次 |
| 删除 | O(1+α) | 定位后摘链，无墓碑烦恼 |
| 空间 | O(m+n) | m 个桶指针 + n 个结点，α 可 > 1 |

## 易错点 / 考点

1. **失败 ASL 的口径**：拉链法失败查找是把"散列到的那条链"扫完，本实现按 m 个桶平均链长统计；手算题按"每个地址可能落到的链长求平均"做，分母是地址数不是元素数。
2. 头插不改变比较次数但改变结点次序：同一批 key 以不同顺序插入，各链内次序不同、成功 ASL 也可能不同——"散列表与插入顺序无关"这个直觉要打折扣，考过判断题。
3. 摘链顺序沿用单链表的老规矩：先让前驱绕过目标再 free，头结点情形（桶头即目标）要单独处理，hc_delete 的 prev==NULL 分支就是。
4. 与开放定址对比是必考题：拉链删除简单、允许 α>1、但指针空间和缓存劣化；一句话记住差异根源——**数据在桶外还是在桶内**。
