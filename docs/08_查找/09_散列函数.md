# 09_散列函数

## 一句话定位

不再逐个比较，用一个函数 H(key) 直接把关键字算成存储地址——查找从"比较的艺术"变成"映射的艺术"，期望 O(1) 的背后要先回答两个问题：怎么映射才均匀，撞车了往哪放（撞车问题归后两篇）。

## 核心概念

前面所有查找结构都在"比较"里打转：折半比一次砍一半，树形比一次走一个分叉，再快也要 O(log n)。散列换思路：知道 key 就能算出它在哪，比较次数趋近于零。设计目标三条——分布均匀（散得开才少冲突）、计算简单（算地址本身要便宜）、冲突可控。五种经典构造法就是三目标在不同数据假设下的取舍：

直接定址法 H(key) = key（或 a·key + b）是恒等映射，零冲突、零浪费，但要求关键字集合小且连续——给 1~150 岁的人员表按年龄建索引很合适，值域一大表就撑爆。注意本实现 hf_direct 不做 %m 压缩（参数 m 只为凑函数签名），key 本身就是桶号，.h 注释里写明了这一点。除留余数法 H(key) = key % p 最常用，p 取不超过表长 m 的最大素数；为什么偏要素数？合数 p 会和有规律的 key（等差数列、周期编号）"共振"，大量 key 挤进少数同余类，素数让 key 的每一位都参与搅动。本实现的 prev_prime(m) 就是干这个的。

剩下三种面向"对数据一无所知"的场景。数字分析法反着来——它需要先验信息：事先统计各位的区分度（手机号前三位全是 1，毫无信息量），挑分布散的几位拼地址。平方取中法取 key² 的中间几位，平方运算把每一位都揉进中间结果，适合不知道分布、key 位数不多的场合。折叠法把很长的 key（订单号、证件号）切段相加再压缩，专门对付位数超长的关键字。本模块的 hf_distribution 还顺带算了卡方统计量检验均匀性，main.c 里能直接看各函数的落桶分布。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 计算散列地址 | O(1) | 五种方法都是常数次算术运算 |
| 直接定址建表 | O(U) | U 为关键字值域宽度，表同值域同宽 |
| 冲突处理后的查找 | 期望 O(1) | 具体取决于装填因子，见 12 篇 |
| 空间 | O(m) | m 个桶；直接定址时 m = 值域宽度 |

## 易错点 / 考点

1. **m 与 p 别混**：m 是表长，p 是除留余数的模（≤m 的最大素数）；表长 m=12 时 p=11，落桶范围只有 [0,11)，手算映射范围按 p 来。
2. 除留余数为什么选素数是高频简答：合数模会让等差/周期性关键字集中同余，素数打散规律；答"素数分布均匀"不算到根上，要说到"让每一位都参与"。
3. 直接定址法的适用条件是选择题陷阱："关键字小而连续"缺一不可，值域稀疏（比如学号 2024001~2024999 跳着用）时直接定址浪费惊人。
4. 五种方法考"适用场景匹配"而不是默写公式：数据有先验规律→数字分析；key 超长→折叠；分布未知→平方取中；要求零冲突且值域小→直接定址；通用首选→除留余数。
