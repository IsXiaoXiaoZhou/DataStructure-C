# 04_二叉排序树

## 一句话定位

把"折半的分法"搬进链式存储：左子树全小、右子树全大，每走一层扔掉一半方向。链式结构里查找 O(log n) 的起点，也是 AVL、红黑树的底座。

## 核心概念

有序数组折半快，但插一个元素要搬半张表；链表插删快，却只能顺着数。二叉排序树（BST）把两头的长处拼起来：每个结点把关键字空间劈成两半，比它小往左走、比它大往右走，查找路径长度就是树高。性质只有一条但要求递归成立——**左子树所有结点 < 根 < 右子树所有结点**，于是中序遍历恰好得到升序序列，这也是手算任何 BST 题的万能验证器。

插入和查找是同一件事：沿比较路径走到底，新结点必然挂成叶子（bst_insert 用 `&(*root)->left` 二级指针递归，空位即插入点，根结点无需特判；重复 key 拒绝插入）。删除分三种情况：叶子直接摘；单孩子让孩子顶上；麻烦的是双孩子——直接拔掉会留下两个孤儿。办法是用**中序前驱（左子树最右结点）的值覆盖被删结点，再去删前驱本尊**。为什么挑前驱？因为左子树最右结点至多带一个左孩子，删它必然归约成前两种简单情况。del_node 里 q 记着前驱的双亲，前驱接在父结点左边还是右边、接管哪个孩子，两种分支源码都处理了。

BST 的命门在树形由插入顺序决定：按 1、2、3…有序插入，每个新结点都挂右边，树直接长成一条链，查找退化成 O(n)——和顺序查找无异。这个病 100 万条有序数据就能暴露，治它的药就是下一节的平衡二叉树。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 查找 / 插入 / 删除 | O(h) | h 为树高，每次下降一层 |
| 平均（随机插入序） | O(log n) | 期望比较次数约 1.39·log₂n |
| 最坏（有序插入） | O(n) | 蜕化成单链表 |
| 中序遍历 | O(n) | 输出升序序列 |
| 空间 | O(n) | 每结点 data + 两指针 |

## 易错点 / 考点

1. **双孩子删除**：值替换 + 删前驱是两步，手算常错在替完值就把整棵左子树搬上来，或忘了前驱的左孩子还要顶到前驱原来的位置。
2. 判"是不是 BST"不能只看每个结点和它的左右孩子：反例 5-3-6（6 是 3 的右孩子），局部合法但 6 落进了 5 的左子树。必须保证左子树整体 < 根，用中序是否升序来判最稳。
3. 有序/接近有序的插入序列导致退化 O(n)，是选择题常客；反过来"给定插入序列画树"要先画后验：中序遍历必须升序。
4. 删除用前驱还是后继都对（考试按题目给的图选更省事的那种），但同一次删除只能选一个；两种选择的树形不同，别中途换。
