# 08_B+树

## 一句话定位

B 树的数据库特化版：真实数据全部搬到叶子、叶子串成升序链表，内结点只留路由键当路标——单点查询多走一层，范围查询少绕一大截。MySQL InnoDB 索引的原型就是它。

## 核心概念

B 树查一个范围（如"分数在 60 到 90 之间"）有多别扭：命中 60 之后要做中序式的上跳回溯，跳一层读一次盘，范围越宽 IO 越碎。B+ 树把数据挪了个位置：内结点只存路由键（本实现取右子树最小键，bplus.h 头注释写明），真实关键字与记录全在叶子，叶子再用链表串起来。于是范围查询变成"先按 lo 下探到叶层，然后沿叶链顺序扫到 hi"，代价 O(log_t n + k)，k 是命中条数——**回溯变成顺序扫描，这正是 B+ 树存在的理由**。

数据搬走的连锁反应都得算账。其一，内结点不再背数据指针，同样大的结点能装更多键，树更矮，单点查找虽然"必须走到叶层才算命中"（在内结点撞上路由键也不能停，那只是个副本）比 B 树多一层，但每层 IO 更省，总体不吃亏。其二，键在叶子和路由上各存一份，删除时祖先的路由键可能要回填。其三，记法有变体：教材 m 阶 B+ 树是"n 棵子树 n 个关键字"，本实现是"n 个键配 n+1 棵子树、路由键 = 右子树最小键"，头注释特意标了这处差异，读 .c 时按实现的记法对号。

删除的简化也值得一看：本实现不做兄弟借位与合并，只摘除变空的叶、沿途回填路由键，键数掉光的内部结点由唯一孩子顶替并级联收缩。这偏离了教材"非根结点至少 ⌈m/2⌉ 棵子树"的下限（可降到 1），头注释里逐条写明了取舍——它是功能正确的简化变体，答题时仍按教材规则来。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 单点查找 | O(log_t n) | 必须下探到叶层，比 B 树多一层 |
| 范围查询 | O(log_t n + k) | 定位 lo 后沿叶链扫 k 条 |
| 插入 | O(log_t n) | 叶满分裂，路由键回填祖先 |
| 删除 | O(log_t n) | 本实现摘空叶、回填路由键，不合并 |
| 空间 | O(n) | 路由键是叶子键的副本，冗余 O(n) 量级 |

## 易错点 / 考点

1. **"内结点也能命中"是 B 树的特权**：B+ 树查找必须到叶层，内结点的键只是路由副本——这条是 B 树/B+ 树辨析的第一高频考点。
2. 分裂上移的内容不同：B 树叶分裂把中间键"搬走"；B+ 树叶分裂上移的键是右半第一键的**副本**，原键仍留在叶子里——手算分裂图最容易在这儿画错。
3. 对范围查询各答一次 IO 次数：B 树中序回溯按命中数乘树高算，B+ 树是 log_t n 次定位 + 顺序读叶链，两者差距是数据库选 B+ 树的直接原因。
4. 记法差异先看清：教材"n 子树 n 键"、本实现"n 键 n+1 子树"，还有删除是否维护 ⌈m/2⌉ 下限——题目按哪种实现出，就按哪种答。
