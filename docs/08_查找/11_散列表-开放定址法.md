# 11_散列表-开放定址法

## 一句话定位

冲突了就在数组里另找空位：不设链、全塞桶内，按探测序列一路试下去。省掉指针换来更紧凑的内存，代价是删除只能立墓碑、表不能装满。

## 核心概念

拉链法把溢出元素放到桶外，开放定址法说：桶数组本身就是全部空间，H(key) 撞车了就按规则找下一个空位。找位的规则叫探测序列：线性探测 Hᵢ = (H(key)+i) % m 最简单，撞了就挪一位；二次探测 Hᵢ = (H(key)+dᵢ) % m，dᵢ 取 1²、−1²、2²、−2²…交替正负跳（负偏移加 m 转正），把探测点撒得更开。线性探测的毛病叫堆积：连续占用的桶连成片，之后任何落进这片区域的 key 都被迫沿着它排队，越排越长——不是同义词也会互相拖累，二次探测正是冲着这个毛病去的。

删除是这套方案的软肋，也是**考试最爱问的"为什么"**：探测序列是连着的，查找遇到空桶就判失败。如果删除时把中间某格真清成空，排在这格后面的同义词就断了线索——查找在空位处停下，可元素明明在后面。所以删除只能打墓碑标记：格子标成"已删"，查找遇墓碑继续往前走、遇空桶才停。墓碑还有个妙用：插入时记住路上遇到的第一个墓碑位（本实现的 first_tomb），最后把元素插进那里回收空间。ho_search 的循环里三种桶状态的处理各司其职，对着源码把这条状态机读一遍，比背十遍定义都牢。

空间全在桶内还有一条硬约束：α = n/m 永远小于 1，表满了就插不进。而且期望探测次数约 1/(1−α)，α=0.7 就要平均 3 次多，α=0.9 直接 10 次起——所以工程实现都在 α 过线时扩容重散（rehash），这一点 12 篇的 α 扫描实验能看到曲线起飞。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 插入 | O(1/(1−α)) | 找空位，探到墓碑可复用 |
| 查找（成功） | O(1/(1−α)) | 沿探测序列比对 |
| 查找（失败） | O(1/(1−α)) | 走到第一个空桶才停 |
| 删除 | O(1/(1−α)) | 只能标墓碑，真实删除需 rehash |
| 空间 | O(m) | 无链结点，但 m 必须大于 n |

## 易错点 / 考点

1. **手算探测序列是重灾区**：线性探测每次 +1；二次探测是 +1、−1、+4、−4、+9…（平方序列不是 1,2,3,4），偏移为负要加 m 转正，落点按 (H+dᵢ) mod m 算。
2. 删除为什么立墓碑要能推出来：真删置空会截断探测链，排在后面的同义词从此查不到；查找的终止条件是空桶，墓碑只"路过"不算命中。
3. 二次探测的覆盖能力别答过头：只有表长取形如 4k+3 的素数时，±i² 交替序列才保证探遍全部 m 个桶位（m=7 可手推验证：0、+1、−1、+4、−4、+9、−9 恰好铺满 0~6）；一般素数只覆盖部分——表长取值的讲究是经典考点。
4. 插入查重与墓碑的次序：沿路遇到 OCCUPIED 且 key 相同要判重复拒绝插入，同时记住第一个墓碑位——直接插进第一个墓碑可能造成同义词出现两份，手算时容易忽略。
