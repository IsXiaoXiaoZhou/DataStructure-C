# 03_分块查找

## 一句话定位

先查一张小索引定块，再进块里顺序扫。靠"索引有序、块内无序"的折中，在折半的速度和不许全表有序的现实之间找平衡。

## 核心概念

全表有序才能折半，可全表有序的代价是插入麻烦：往中间插一个，后面全体挪窝。分块查找把"有序"降格成"块间有序"——第 i 块的最大关键字小于第 i+1 块的最小关键字，块内爱怎么排怎么排。于是查找分成两阶段：先在索引表里定位该进哪块，索引表按各块 max_key 升序，可以折半；再进那块顺序扫，块小，扫一遍不亏，也不用为查找付排序的账。

定块这步有个细节值得对照源码看：本实现 blk_search 的折半找的是**第一个 max_key >= key 的块**，不是精确命中某个块——key 落在两块的交界处（比上一块最大值大、比这块最大值小）时，就该进这一块再往后翻。这是折半的"下界"变形，.c 里 `first = m` 先记候选再收缩，正是在找这个下界。

块长怎么取也有讲究。索引用顺序查找时，成功 ASL ≈ (块数+1)/2 + (块长+1)/2，且 块数×块长 = n，对块长求极值得块长 √n，此时 ASL ≈ √n + 1。直觉上两头都要付钱：块切太细索引变长，切太粗块内变慢，√n 恰好两头平衡。本实现的 blk_search 还带 `cmp` 出参精确统计比较次数，跑 main.c 能拿实测和这个理论值对照。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 索引定块（折半） | O(log b) | b 为块数；顺序定块为 O(b) |
| 块内查找 | O(L) | L 为块长，块内无序只能扫 |
| 合计（块长 √n） | O(√n) | 最优 ASL ≈ √n + 1 |
| 建索引 blk_build_index | O(n) | 每块扫一遍取最大值 |
| 空间 | O(b) | 索引表每块一项（max_key/start/len） |

## 易错点 / 考点

1. **定块边界**：折半索引表找的是"第一个 max_key >= key"的下界，不是等值命中；key 比所有块的最大值都大才判失败。手算时按等值折半套模板，是最常见的翻车点。
2. 块内不能提前终止：块内无序，扫到比 key 大不能停（后面可能还有），必须命中即停或扫完整块——除非题目明说块内也有序。
3. 插入只需挂到对应块尾：块内无序意味着新元素不用搬动其他元素，这是分块相对全有序表的核心优势，选择题爱考"为什么插入代价低"。
4. 最优块长手算题：给 n 求"最佳块长与最小 ASL"，答块长 √n、ASL ≈ √n+1（前提是索引也用顺序查找）；题目若说索引用折半，公式就变了，看清条件再套。
