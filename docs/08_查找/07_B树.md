# 07_B树

## 一句话定位

面向磁盘的多路平衡查找树：一个结点对应一次读盘，结点里塞几十上百个关键字把树压矮——用"结点内多比几次"换"少读几次盘"。

## 核心概念

红黑树再平衡也是二叉：100 万条数据树高约 20，每层结点在不同磁盘块上，一次查找就是 20 次磁盘 IO，而磁盘 IO 比内存比较慢几个数量级。磁盘按块读，读 1 个关键字和读 200 个代价几乎一样——既然一个块白送这么大空间，那就把一个结点做成一个块，塞满关键字。B 树因此是"矮胖"的：本实现最小度数 t=3，结点关键字在 [t-1, 2t-1]（对应教材 m 阶记法 m=2t，即 m=6 阶）；真实数据库里一个结点几百个键，10 亿条数据树高也只有 3~4，**树高就是 IO 次数**，这是理解 B 树一切设计的锚点。

它的形态约束都服务于"矮而稳"：结点内关键字升序，孩子数 = 关键字数 + 1，子树区间互不重叠；所有叶子强制同一层，任何查找走的层数一样，IO 次数也就一样均衡。叶子永远等深的秘密在插入策略里：本实现是自顶向下的"先分裂再下降"——下降路上遇到满孩子就当场分裂，等真走到叶子时父辈们必有空位，插完不用回溯。分裂的动作是**把中间键上移给父结点，左右各留 t-1 个键**，只有根分裂才让树长高一层，所以树只从顶上长、叶子永远齐平。

删除是插入的逆操作，规则要繁一些：自顶向下保证路过结点至少 t 个键，内部结点命中时用前驱/后继键顶替，不足则向兄弟借键，兄弟也不富余就和父键三者合并。看 btree.c 的 borrow_or_merge 和 merge_children，注释把"借不到就合"的次序写得很清楚。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 查找 | O(t·log_t n) | 每层结点内扫 O(t) 个键，共 log_t n 层 |
| 插入 | O(t·log_t n) | 下降至多每层分裂一次 |
| 删除 | O(t·log_t n) | 借位/合并可能级联 |
| 空间 | O(n) | 结点至少半满，利用率 ≥ 50% |

## 易错点 / 考点

1. **分裂上移哪一刀**：2t-1 个键分裂，中间第 t 个键上移父结点，左右各留 t-1 个；手算最常错把中间键留在左半、或忘了孩子指针要跟着对半分。
2. 新键永远落在叶子：中途的分裂只是给下降路径让路，别把新键插进内结点；根分裂是树长高的唯一途径，所以叶子天然等深。
3. 阶数换算看清记法：王道讲 m 阶（孩子数上限 m，关键字 [⌈m/2⌉−1, m−1]），本实现用最小度 t 表述（关键字 [t−1, 2t−1]，等价 m=2t），做题先统一成同一种语言。
4. "为什么叶子必须同层"常被问：叶子等深 → 任何查找路径等长 → 每次 IO 次数可预期，这是磁盘场景的硬需求，不是对称美观问题。
