# 06_红黑树

## 一句话定位

把 AVL 的"严格平衡"放宽成"黑高一致的近似平衡"：用颜色记账换掉大半旋转，工程性价比让它在 STL map、Linux 内核里无处不在。

## 核心概念

AVL 的严格是有代价的：删除一路旋到根不罕见，插入场景一多，旋转的开销就开始咬人。红黑树的思路是退半步——不追求左右子树一样高，只靠五条性质把"失衡程度"锁住：①每个结点非红即黑；②根是黑色；③每个 NULL 叶视为黑色；④红结点的孩子必黑（等价于无相邻红）；⑤任一结点到所有后代叶的路径含相同个数的黑结点（黑高相等）。

为什么"近似平衡"就够用了？性质⑤保证最短路径全黑、长度为黑高 h；性质④保证红色不相邻，最长路径最多红黑相间、长度 2h。所以**最长路不超过最短路的 2 倍，树高 ≤ 2·log₂(n+1)**——比 AVL 的 1.44·log₂n 松，但仍是 O(log n)，查找只慢个常数因子。

省下来的是旋转次数。插入时新结点一律染红：红色不改变黑高，只可能违反"父红"（或根红），修复是局部动作——叔红就把父叔染黑、祖父染红，冲突向上移一层接着看；叔黑才旋转，形态与 AVL 的四种旋转型号同构。变色的路一路推上去不花旋转，真正转起来至多 2 次；删除也至多 3 次。本实现按 CLRS 风格带 parent 指针，insert_fixup 的注释把"叔红变色上移、叔黑旋转"这两句话写得很直白。工程的取舍也就清楚了：读多写少选 AVL（更矮），插删频繁选红黑。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 查找 | O(log n) | 高度 ≤ 2·log₂(n+1) |
| 插入 | O(log n) | 修复至多 2 次旋转，其余靠变色 |
| 删除 | O(log n) | 修复至多 3 次旋转 |
| 空间 | O(n) | 每结点多一个 color、一个 parent |

## 易错点 / 考点

1. **性质③的坑**：NULL 空叶算黑色结点，手算黑高时每个路径末端要补一个；漏数它，性质⑤的判断就全错。
2. "最长路 ≤ 2×最短路"的推导要会写：最短路全黑 = h，最长路红黑相间 = 2h，靠性质④⑤两句话，这是简答题标准答案。
3. 新结点为什么染红不染黑：染黑必破坏性质⑤（黑高变了），修复牵动全树；染红只可能违反性质②④，叔红变色、叔黑旋转，都是局部动作。
4. 叔红变色后不能收工：祖父被染红，要把它当"新插入的红色结点"继续向上检查，可能连锁变色直到根；手算时只处理一层就停是常见错误。
