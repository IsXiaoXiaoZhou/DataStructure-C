# 01_顺序查找

## 一句话定位

从表头到表尾逐个比对，命中即停、扫完即败。它不要求有序、不要求随机存取，链表和无序数组都吃得下——是所有查找里最不挑条件的兜底方案。

## 核心概念

折半查找快，但先决条件一堆：要顺序存储、要有序。手里的数据是一条乱序链表时，唯一的选择就是从头数到尾。顺序查找的代价可以用平均查找长度（ASL）算清楚：等概率下命中第 i 个要比较 i 次，成功 ASL = (1+2+…+n)/n = (n+1)/2。1 万个元素平均要比对约 5000 次，数据一大它就只是"能查"而谈不上"快"。

朴素版每轮其实做了两次比较：`a[i] == key` 是一次，循环条件里的 `i < n` 也是一次。查不到时后者要白花 n 次，纯粹的边界开销。哨兵版把这笔账省下来：先把 key 拷一份埋在 `a[n]`，循环条件只剩 `a[i] != key`——表里没有它也必然在哨兵处命中，循环照样能停，边界判断被这一份拷贝整个吸收掉了。出循环后 `i < n` 说明命中的是数据区，`i == n` 说明命中的是哨兵，即没找到。

这就是**哨兵省的不是关键字比较，而是 n 次越界判断**。思想与快排的 pivot 挡板、KMP 的 next 同源：预埋一个"必然成立"的条件，把循环不变量从每轮一次压成全程一次。代价也写在签名里：`seq_search_sentinel` 的 `a[]` 不带 const，表底还得多留一个格子，顺序表要按 n+1 开——这正是 .h 注释里"均摊省掉 ~n 次边界比较"的来由。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 朴素版·成功 | O(n) | ASL = (n+1)/2 |
| 朴素版·失败 | O(n) | 必比满 n 个元素（含 n+1 次边界判断） |
| 哨兵版 | O(n) | 每轮少判一次 i<n，量级不变、常数更小 |
| 空间 | O(1) | 哨兵版要求表尾多一个可写位置 |

## 易错点 / 考点

1. **失败时的比较次数**：朴素版失败比 n 个元素、判 n+1 次边界；哨兵版失败同样 n+1 次比较，但最后一次比的是哨兵——"哨兵命中也算一次比较"是选择题陷阱。
2. ASL 公式有前提：成功 ASL=(n+1)/2 默认各元素等概率；给概率分布的题要按 Σpᵢ·cᵢ 重算，把高频元素放表头才降 ASL。
3. 哨兵版的手写坑：表长必须开 n+1，否则 `a[n] = key` 就是越界写；表只读（const 数组、共享内存）时哨兵版用不了。
4. 有序表上做顺序查找可以提前终止：扫到第一个比 key 大的元素就能判败，失败不必扫满全表——但成功 ASL 不变，这一点常被出成判断题。
