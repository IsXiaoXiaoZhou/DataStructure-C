# 02_折半查找（插值查找、斐波那契查找）

## 一句话定位

有序表上的"猜中间"游戏：每次和 mid 比一下就把候选区间砍一半，10 万个元素至多 17 次比较定生死。本模块三种变体只差一件事——mid 选在哪。

## 核心概念

顺序查找的 5000 次平均比较，问题出在"每个位置都平等对待"。有序表给了新信息：比过 a[mid] 还小，mid 右边的整段都可以扔。折半查找把区间 [low, high] 反复对折，直到只剩一个候选：n 个元素至多比 ⌈log₂(n+1)⌉ 次，10 万元素封顶 17 次。mid 的落点画一下就懂——`mid = low + (high - low) / 2` 向下取整，落在区间中点偏左；key 小则右界收到 mid-1，key 大则左界抬到 mid+1，闭区间 [low, high] 配 `low <= high` 循环。写成 `low + (high-low)/2` 而不是 `(low+high)/2`，是防两个下标相加溢出。

插值查找改的不是结构，是猜测策略：查字典找"张"不会翻正中间，而是直接翻到靠后的位置。它按 key 在当前值域里的占比定点：`mid = low + (high-low)·(key-a[low])/(a[high]-a[low])`。数据均匀分布时一步就能落到目标附近，期望 O(log log n)；代价是分布偏斜时退化，最坏掉回 O(n)。实现里有两处保命判断：区间端点同值（除零）直接比对，key 落在值域外直接判败——这两行在 .c 里都有注释。

斐波那契查找解决的是另一个问题：早期机器除法昂贵，能否只用加减定 mid？斐波那契数列天然可加性拆分——F[k] = F[k-1] + F[k-2]，表长向上补到 F[k]-1，mid 取 `low + F[k-1] - 1`，正好按黄金比例（约 1:1.618）切分，接近对半。往左走剩 F[k-1]-1 个元素、k 减 1；往右走剩 F[k-2]-1 个、k 减 2；补出来的虚拟位当 +∞ 处理，key 必然走左半。三兄弟同为"折半家族"，考题最爱横着比。

## 复杂度表

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 折半 成功/失败 | O(log n) | 10 万元素 ≤ 17 次比较 |
| 插值（均匀分布） | O(log log n) | 一次插值就贴近目标 |
| 插值（分布偏斜） | 最坏 O(n) | 值挤在一角时比例失灵 |
| 斐波那契 | O(log n) | 定 mid 只用加减，不比折半慢 |
| 空间 | O(1) | 三者都只动几个下标 |

## 易错点 / 考点

1. **mid 取整方向**：`(low+high)/2` 向下取整，mid 偏左，手算区间要跟着往左缩；有的题写 `(low+high+1)/2` 向上取整，也正确，但边界收缩必须配套——方向和收缩规则不一致才会错。
2. 循环条件是 `low <= high` 还是 `low < high`：闭区间写法配 `<=`，漏了等号，区间只剩 1 个元素（low==high）时会漏查。
3. 插值公式手算：分子是 `key - a[low]`、分母是 `a[high] - a[low]`，别把分母写成表长 n；区间缩小后要用当前 low/high 端点的值，不是全表首尾。
4. 斐波那契走位记忆：往左 k 减 1、往右 k 减 2——左半对应 F[k-1]，右半对应 F[k-2]。手算时先补表长到 F[k]-1 再开始切，虚拟位当 +∞ 只往左走。
